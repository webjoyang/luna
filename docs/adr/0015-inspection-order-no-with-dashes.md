# ADR-0015：检验单号带连字符分隔（刻意不一致项目编号惯例）

**状态**：Accepted
**日期**：2026-09-21
**关联**：生产管理-检验单 MVP

## 背景

项目既有单据编号均**不带连字符分隔**，前缀与流水直接拼接：
- 销售合同 `CH20260001`（CH + 年 + 4 位）
- 胚布单 `PB0919001`（PB + 月日 4 位 + 3 位，按天）
- 纱线采购单 `YP20260920001`（YP + 年月日 8 位 + 3 位，按天）
- 供应商 `SUP20260001`（SUP + 年 + 4 位）

用户决策检验单号采用 `INS-20260921-001` 格式：`INS` + `-` + 年月日 8 位 + `-` + 3 位日流水，带两个连字符分隔。这与项目编号惯例不一致。

## 决策

检验单号采用带连字符格式 `INS-YYYYMMDD-NNN`（如 `INS-20260921-001`），按天取号，租户内全量唯一、软删不释放（编号唯一索引含已删除行，仿 ADR-0005/ADR-0006）。

## 理由

用户在 grill-with-docs 阶段明确选择此格式。带连字符的可读性优于纯数字拼接（`INS-20260921-001` 比 `INS20260921001` 更易肉眼分段），且检验单号常出现在录检现场的单据/标签上，可读性有实际价值。

## 反向权衡

- **惯例不一致**：项目其他单据编号无连字符，检验单成为唯一带分隔符的编号，需在 GLOSSARY.md 与代码注释中标注，避免后续开发者误以为应统一。
- **取号/查重逻辑复用**：编号生成与查重逻辑复用既有 `SupplierServiceImpl`/`YarnOrderServiceImpl` 的取号重试机制，仅格式串不同，实现成本无差异。
- **唯一索引**：连字符不影响唯一索引语义，`(tenant_id, code)` 索引照常生效。

后续若发现连字符在某个下游（如条码生成、URL 路径）引起问题，可回退为无连字符格式（改格式串即可，数据迁移用 `REPLACE(code, '-', '')`）。
