# ADR-0019：质检确认以检验单录检明细为源、显式幂等生成

**状态**：Accepted
**日期**：2026-09-25
**关联**：生产管理-质检确认 MVP；ADR-0013（检验同步入库延后）、ADR-0014（录检明细独立子资源）

## 背景

参考项目（linaagi）的质检确认挂在**入库明细**上：检验结果经"检验同步入库"服务写入 `StockInItem.rollStatus`（待复检/不合格）后，由同步钩子按卷自动生成待确认记录。

新项目有两个现实差异：

1. 入库明细没有卷级质量字段（无 rollStatus / 疵点 / 机台号），且检验同步入库经 ADR-0013 明确延后——入库单模块本身虽已建成（ADR-0016/0017/0018），同步链路至今未实现，旧钩子无挂载点。
2. 逐卷录检数据在检验单模块已经就绪：`InspectionOrderItem` 含 rollNo/vatNo/grade（A/B/C/DEFECTIVE）/machineNo/重量/米数/产品快照（ADR-0014）。

## 决策

- **数据源**：质检确认的卷级来源是**检验单录检明细**，不是入库明细。生成时从明细快照卷号、缸号、等级、机台号、产品、颜色、重量、米数等展示字段，并保存检验单 ID/单号与明细 ID 的逻辑关联（不建数据库外键，同项目惯例）。
- **触发等级**：等级为 `B` / `C` / `DEFECTIVE` 的卷（凡非一等品）；A 不生成。
- **生成方式**：检验单工作台提供"生成质检确认"**显式动作**，幂等扫描——同一录检卷只允许存在一条有效（非 REVOKED）确认记录，重复点击只补新卷，返回"新增 X 条 / 跳过 Y 条"。检验单 `ACTIVE`/`COMPLETED` 状态可生成，`DRAFT`/`CANCELLED` 不可。
- **不回写不级联**：生成即快照，检验单或明细事后改等级、改卷号、删除均不影响已生成记录（对齐库存域对上游单据"零回写"惯例）。

## 为什么是显式动作而不是保存钩子

旧系统的自动生成挂在"同步入库"这一明确的流程关口上；新项目没有这个关口。若挂到录检明细保存上，录检是 DRAFT→ACTIVE→COMPLETED 的渐进过程，会带来草稿噪音、等级反复修改的联动、删卷清理等一系列复杂问题。幂等的显式按钮把"什么时候要认定"的控制权交给现场，且可安全重复点击，行为可预测。

## 后果

- 质检确认 MVP 不依赖检验同步入库，该链路未来上线时本模块无需改造（届时若要在入库侧另加联动，另行决策）。
- 已生成记录与源单脱耦：源单改错后，待确认记录只能以 `WAIVED` 免扣认定结案（记录一律不可删，见 ADR-0020）；重新达到生成条件的卷因幂等检查不会重复生成。
- 生成按钮在检验单工作台，但权限使用质检确认自己的 `:generate` 权限码，不挂检验单的更新权限——生成动作创建的是质检确认域的数据。
