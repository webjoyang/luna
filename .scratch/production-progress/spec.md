# Spec：生产管理-生产进度（合同锚点全链路进度跟踪 + 发染记录）

Status: ready-for-agent

> 本 spec 由 grill-with-docs 访谈（3 轮、21+ 项决策）综合而成。术语遵循 [GLOSSARY.md](../../docs/contexts/production/GLOSSARY.md)；架构依据：设计文档 `.trae/documents/contract-progress-architecture-design.md`、ADR-0033（发染记录）、ADR-0034（生产进度只读聚合视图）、ADR-0031（进度反馈）、ADR-0017（通用库存流水）、ADR-0027（发纱不足拦截先例）。

## Problem Statement

旧系统（linaagi）的订单进度（OrderProgress）靠跟单员手动填进度字符串，与胚布/染色/检验三张指示单是两条平行线；"胚布发染厂"环节（拉胚记录）挂在订单上且扣库存不写流水；跨合同进度靠前端拉三个接口按文本弱关联拼凑。同一维度出现三套口径（订单拉胚量、指示单入库量、缸卡排产量），数据孤岛与口径漂移是结构性缺陷。

新系统已删除订单实体（销售合同是唯一锚点），胚布→染厂的物流环节在数据上断链：进度反馈（ADR-0031）只覆盖"染色执行"，不覆盖"发去染厂"；且没有任何界面能看到一份合同从下料到出货的全链路进度。跟单员只能逐个打开胚布单、染色单、入库单、发货单人工拼进度。

## Solution

两件事：

1. **补齐断链环节**——新增"发染记录"（GreigeDispatchRecord）：挂胚布单的轻量流转记录，创建写 `PROCESS_OUT` 库存流水（不足拦截）、删除写红冲，可补填指向染色单，建立"胚布单→染厂"的物流血缘。
2. **新增"生产进度"只读聚合视图**（ProductionProgress）：以销售合同为锚点，从下游执行单据与库存流水实时聚合胚布/染色/检验/入库/发货五环节数量与三条预警，提供跨合同列表页（按交期排序筛选）与单合同全链路抽屉。不是表、不是另一张单，没有任何手动进度字段——旧系统手动字符串被根除。

MVP 范围为核心链路：发染记录（后端+双入口）+ 生产进度查询服务 + 独立"生产进度"菜单页。

## User Stories

1. As a 仓库/跟单员， I want 在胚布单上登记一条发染记录（日期/数量 KG/匹数/仓库/染厂）， so that 系统知道这批胚布何时发往哪家染厂。
2. As a 仓库/跟单员， I want 发染时从启用仓中选择出库仓库， so that 库存流水记在正确的仓上。
3. As a 仓库/跟单员， I want 创建发染记录时系统自动扣减胚布库存并留痕流水， so that 库存账与实物流转一致、可追溯。
4. As a 仓库/跟单员， I want 同仓同产品余额不足时创建被拦截并看到需求量/可用量， so that 不会产生账面负库存（直发场景先补入库再发染）。
5. As a 仓库/跟单员， I want 一张胚布单分多次发运时登记多条发染记录， so that 分批发染的节奏被如实记录。
6. As a 仓库/跟单员， I want 删除发染记录时系统自动红冲恢复库存， so that 录错的记录可以安全撤销且账可对。
7. As a 跟单员， I want 事后补填发染记录指向的染色单与染厂， so that 下单时未定的染单可以在确定后补上血缘。
8. As a 跟单员， I want 补填染色单时系统校验与胚布单同一合同， so that 进度血缘不会跨合同错乱。
9. As a 跟单员， I want 发染记录的数量/日期/匹数/仓库创建后锁定、只允许改染色单/染厂/备注， so that 库存流水口径始终简单可信（错删重录）。
10. As a 跟单员， I want 在染色单工作台的"发染记录"页签看到这张单收了多少胚布并可新增， so that 从染单视角也能操作发染（双入口，同一套数据）。
11. As a 跟单员， I want 在胚布单列表直接打开"发染记录"抽屉查看该单发染历史， so that 不用进编辑页就能完成发染登记。
12. As a 跟单员， I want 发染不回写胚布单/染色单状态， so that 单据状态不被下游动作意外改动（零回写惯例）。
13. As a 业务员/跟单员， I want 打开"生产管理→生产进度"页看到全部进行中合同的全链路进度列表， so that 不用逐张单据翻查。
14. As a 业务员/跟单员， I want 列表默认按交期升序（无交期排最后）并可按合同号/客户搜索， so that 最紧急的合同排在最前。
15. As a 跟单员， I want 用"仅看有预警"过滤， so that 一眼聚焦有风险的合同。
16. As a 跟单员， I want 点开单合同抽屉看到胚布（计划/入库/已发染/自织进度）、染色（投染/排产覆盖率/缸状态/延期缸）、检验（录检数/等级汇总）、入库（胚布/成品）、发货（已发/未发）六个环节数量， so that 全链路进度一屏尽览。
17. As a 跟单员， I want 抽屉中能下钻该合同的发染记录列表与缸状态汇总， so that 汇总异常时能追到明细。
18. As a 管理层/跟单主管， I want 合同交期 ≤7 天未发完标记"临期"、交期已过未发完标记"超期"、存在延期缸标记"延期缸"， so that 每天晨会能快速排雷。
19. As a 管理层， I want 进度数据全部从下游执行单据与流水自动聚合， so that 任何人都不能也不需要手动"改进度"，口径永远唯一。
20. As a 业务员， I want M 单位合同的明细原样展示但不混入 KG 合计， so that 跨单位数字不会被折算误差污染。
21. As a 业务员， I want 已取消的合同与单据不进进度统计（可切换查看）， so that 作废数据不干扰在产视图。
22. As a 系统管理员， I want 发染记录与生产进度分别使用独立权限码（query/create/delete）， so that 录入与查询分权。
23. As a 前端开发者， I want 生产进度与发染记录复用同一套后端接口， so that 后续合同工作台页签与看板 widget 可直接接入而不用改后端。

## Implementation Decisions

**命名体系**（用户决策）：菜单"生产管理 → 生产进度"；概念 `ProductionProgress`、视图 `ProductionProgressView`；发染记录 `GreigeDispatchRecord`。避免"订单进度/合同进度/ContractProgress"旧命名。

**范围（MVP = 核心链路）**：
- 后端（lunaerp 模块 `production` 子包）：GreigeDispatchRecord 的 DO/Mapper/Service/Controller；StockLedger 交易类型新增 `PROCESS_OUT` / `PROCESS_OUT_REVERSAL`；ProductionProgressQueryService + ProductionProgressView DTO，暴露 `page`（跨合同列表）与 `get`（单合同全链路）两个只读接口。
- 前端（lunaerp-elmui）：独立"生产进度"页（列表 + 单合同抽屉）；发染记录双入口——胚布单列表行操作抽屉 + 染色单工作台新页签；两入口复用同一弹窗与同一套接口。
- 菜单与权限 SQL：`lunaerp:production-progress:query`；`lunaerp:greige-dispatch-record:query|create|delete`。错误码新开 `1-030-018` 段（发染记录）、`1-030-019` 段（生产进度，只读预留）。

**发染记录关键决策**（ADR-0033）：
- 挂胚布单（greigeOrderId 必填）；dyeingOrderId/染厂可空可补填，补填时校验与胚布单同合同；一张胚布单可多条记录（分批发运），已发染量 = 有效记录合计。
- 粒度按胚布单整单一条（产品快照取胚布单品种，颜色不细分）；无业务编号；软删除。
- 创建即生效同事务写 `PROCESS_OUT` 负流水（仓库弹窗必选、仅启用仓、记录存仓库快照，红冲沿用同仓）；删除写 `PROCESS_OUT_REVERSAL` 正红冲关联原流水。
- 库存不足拦截（返回需求量/可用量），同领纱发纱先例；直发场景须先补入库单。
- 受限编辑：仅染色单/染厂/备注可改，数量/日期/匹数/仓库锁定；错删重录。
- 零回写胚布单与染色单状态。

**生产进度关键决策**（ADR-0034）：
- 只读聚合视图（DTO 不落库），合同为唯一锚点，合同侧不加任何进度字段。
- 聚合路径 **join 反查**：不给库存流水表加合同列；入库/发货按 `related_doc_type + related_doc_id` join 入库单/发货单取合同；发染量从发染记录表经胚布单聚合；染色环节数据来自进度反馈覆盖层（外发黑盒手动代录），其余环节自动聚合。
- 胚布/成品入库区分：按入库单 greigeOrderId / dyeingOrderId 非空判断；约定两者不同时填、不强校验（不改现有入库单行为）。
- 单位口径：只聚合 KG，M 明细原样展示不进合计，不折算。
- 取消单口径：一律排除 CANCELLED（合同默认不进列表可切换；各环节只统计非取消单据）。
- 预警三条：临期（交期 ≤7 天且未发完）、超期（交期已过且未发完）、延期缸（复用进度反馈延期判定）；只读计算不可手工维护。
- 性能：page 按页内合同 ID 集合逐环节批量聚合（IN + GROUP BY，无 N+1）；无定时任务/物化/缓存。
- 列表列：合同号/客户/业务员/交期/状态/demandKg/plannedKg（胚布、染色）/sentToDyeingKg/vatCoverage/greigeInKg、finishedInKg/shippedKg、unshippedKg/预警数；筛选：关键字、交期范围、状态、仅看有预警；默认按交期升序、无交期排最后。
- 抽屉：头部合同信息 + 预警标签；六环节分区卡片；下钻先做发染记录列表与缸状态汇总。

**零回写边界**：发染不回写胚布/染色状态；入库不回写上游；发货不回写合同；进度反馈不回写染色单；唯一例外仍是布票→织造单/机台任务（ADR-0024）。

**Schema 变更**：新建 `lunaerp_production_greige_dispatch_record` 表；`lunaerp_stock_ledger.txn_type` 枚举扩两个值（代码层枚举，非字典）；无其他表结构变更，不迁移历史数据。

## Testing Decisions

- **只测外部行为**：断言 Service 公开方法的结果（返回值、写出的流水内容、抛出的错误码），不断言内部调用序列。
- **唯一 seam**：后端 Service 层（现有最高 seam，不新开 seam）。发染记录测 `GreigeDispatchRecordService`：过账/红冲流水内容、余额不足拦截、受限编辑校验、同合同校验、多次发染合计。生产进度测 `ProductionProgressQueryService`：各环节聚合口径（KG 过滤、CANCELLED 排除、join 反查取合同、胚布/成品入库区分、预警三条触发边界、无交期排序）。
- **先例**：进度反馈的 Service 层单测（mock Mapper 方式）与错误码常量测试即现有同型测试，直接仿照。
- 前端无测试基建：按设计文档"验证方式"清单做手工验收（口径与各单据侧展示一致、库存闭环、双入口数据一致）。

## Out of Scope

- 销售合同工作台及其"生产进度"页签（合同工作台骨架未建，后置，复用 `get` 接口）
- 跨合同生产进度看板 widget（对标旧系统 ContractProgressWidget，后置，复用 `page` 接口）
- 直发免入库（发染不写流水仅登记物流）；颜色级发染血缘（挂颜色行）
- 给库存流水表加合同列 / 历史数据回填
- M 单位折算、损耗分析、AI 排产建议、晨会排雷简报（alerts 已预留）、客户门户、移动端、消息推送
- 订单实体的任何形式回归（不建订单表、不加合同进度字段）
