# ADR-0022：胚布单扩展"自织"生产模式，与外发同表承载

**状态**：Accepted
**日期**：2026-09-25
**关联**：生产管理-织造执行；ADR-0006（胚布单号按天取号）

## 背景

新项目胚布单（`GreigeOrder`）原语义为"向**外部坯布厂**下达的织布委托单"，承织坯布厂必填。
参考系统（linaagi）中，织造执行的上游是 `GreigeInstruction`（胚布指示单）——它既承载自产计划也承载外发：
`GreigeInstruction → WeavingBatch → MachineTask → WeavingTicket`。本厂车间排产即从指示单创建织造批次。

新项目要落地自有车间的织造执行，必须先回答"自产计划记在哪"：

- 方案一：修改胚布单语义，自织与外发同表，以字段区分；
- 方案二：新建"自产计划单"实体，与胚布单并列；
- 方案三：织造单不依赖任何上游，手工填产品与数量。

## 决策

采用方案一：胚布单增加 `production_mode` 字段，字典 `lunaerp_greige_production_mode`：

- `OUTSOURCE` 外发（**缺省**，存量数据与既有页面行为不变）；
- `SELF` 自织（本厂车间织造，是织造单的唯一合法来源）。

配套规则：

1. **承织坯布厂可空性随模式变化**：OUTSOURCE 必填，SELF 可空。不引入"本厂"占位供应商——假供应商会污染供应商档案与外发统计口径。
2. **零回写**：织造单侧的实际进度不回写胚布单状态。胚布单详情对 SELF 单实时聚合展示"已织匹数/计划匹数"只读进度（不落库字段）。
3. 胚布单自身状态机（ACTIVE/COMPLETED/CANCELLED）不因本次改造改变。
4. 自织胚布单的创建表单复用现有胚布单表单，仅增加模式切换并联动承织厂必填校验。

## 索引设计（回应"可空列会不会慢"）

承织厂列可空不影响走索引——PostgreSQL B-tree 索引包含 NULL。索引按查询模式建：

- `(tenant_id, greige_factory_id)`：按承织厂过滤；
- `(tenant_id, production_mode)`：按模式过滤；自织行数少时改用**部分索引** `WHERE production_mode = 'SELF'`，索引体小、命中快。

## 后果

- 胚布单成为织布生产的统一源头单据，外发与自织单据编号规则、列表、审计完全同构，减少一套并行实体。
- 语义加宽是刻意代价：所有胚布单查询/统计若需区分口径，必须显式按 `production_mode` 过滤；新建统计视图默认口径需在评审时确认。
- 方案二被否的理由：自产计划与外发委托在字段层面高度重合（品种、规格、数量、交期），另建实体会带来重复表单与跨口径合并成本；未来若两路径字段分化严重，可再拆分，存量数据迁移成本可接受。
