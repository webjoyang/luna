# 0006 — 胚布单号按日取号：PB + 月日 + 3 位日流水

## 状态

accepted

## 上下文与决定

胚布单号 `greigeOrderNo` 形如 `PB0919001`（`PB` + 两位月 + 两位日 + 3 位顺序号，超 999 自然扩位），租户内全量唯一。顺序号的重置口径是**按天**：每天从 001 起，只扫描"本租户 + 当天前缀"的已有编号取数字后缀 max+1。这与销售合同号 `CH`（ADR-0004）、供应商号 `SUP`（ADR-0005）的**按年**取号口径刻意不同。

唯一性口径与合同/供应商一致：普通唯一索引 `UNIQUE (tenant_id, order_no)`（不带 `WHERE deleted = 0`），软删不释放编号；取号与手填查重扫描含已删除行，绕过 MyBatis-Plus 逻辑删除自动过滤；新建缺省服务端生成、也可手填，撞号报 `1_030_006_001`。

## 理由

1. **对齐工厂线下票据习惯**：胚布单是下达给坯布厂的高频厂内生产单据，当天的布票/交接凭据需要连续可点。编号内嵌月日，单据纸质交接时仅凭号即可识别日期；按年序列（如 PB20260153）不内嵌日信息，纸质场景不直观。
2. **容量充足**：单个租户单日胚布单量远低于 999 上限，3 位日流水不会溢出，溢出时自然扩位即可。
3. **旧系统已验证**：旧系统（linaagi）胚布单号即 `PB` + 月日 + 3 位流水，业务方已习惯该格式。

## 考虑过的备选

- **按年取号 `PB` + 年份 + 4 位（对齐 CH/SUP）**：全系统取号口径统一，且编号跨年连续。但胚布单是厂内高频单据而非对外签约/对账单据，编号的"日期可读"价值高于"口径统一"；跨单据的一致性让位于纸质交接场景。未来工程师看到 PB 与 CH/SUP 重置口径不同，**不应**将其"修正"为按年。
- **数据库序列 / Redis 按日计数**：需处理跨租户与每日零点重置的额外复杂度，沿用已验证的"租户内前缀扫描 + 数字后缀 max+1"方案即可（日扫描范围更小）。

## 后果

- 取号扫描以"服务器当天日期"构造前缀；跨零点保存单据时编号归入实际保存日，符合业务直觉。
- 不同天的流水号会重复（如 PB0919001 与 PB0920001），唯一性由 `(tenant_id, order_no)` 整体保证，前缀不同不冲突。
- 取号/查重 Mapper 方法需显式包含已删除行，实现处注释标明意图，防止被当疏漏"修复"（同 ADR-0004/0005 后果）。
