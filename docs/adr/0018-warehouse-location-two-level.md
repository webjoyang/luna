# ADR-0018：仓库/库位两级基础模型 + 入库多库位分配放置

**状态**：Accepted
**日期**：2026-09-23
**对应旧系统**：linaagi WarehouseMap/WarehouseZone/WarehouseLocation/InventoryPlacement（schema.prisma L3735-L3878）

## 背景

旧系统仓储主数据是重型模型：`WarehouseMap`（2D 平面图画布，长宽高/形状/版本）→ `WarehouseZone`（多边形库区，容量、允许存货类型、多边形 JSON）→ `WarehouseLocation`（行列层 + xyz 立体坐标、容量、二维码），另有 `InventoryPlacement`（入库明细到库位的放置记录）与 `InventoryMovementLog`（移库流水）。

用户要求新系统 MVP 具备"基本的仓库和库位"，并像旧系统一样在入库明细里逐匹"分配库位"。需要决定主数据层级深度与放置记录的形态。

## 决策

### 1. 主数据：仓库 + 库位两级简版

- **仓库 `lunaerp_stock_warehouse`**：编号（WH+年份+4 位流水，服务端取号/可手填、租户唯一含软删行）、名称必填、地址、状态（ACTIVE/INACTIVE，不建字典）、备注。
- **库位 `lunaerp_stock_warehouse_location`**：属于一个仓库；编码手填（如 `A-01-02`），**同一仓库内唯一**；名称、排序、状态、备注。
- 明确**不建**：库区（zone）、平面图/画布、行列层与 xyz 坐标、容量（capacityKg/Rolls）、二维码、移库日志。
- 删除守卫：仓库下有库位或已被入库单引用 → 禁止删除，引导改用停用；库位被放置记录引用 → 禁止删除。停用档案不出现在新单选择项，历史快照不受影响。
- 仓库/库位主从同页管理（一个"仓库管理"菜单），不拆两个菜单。

### 2. 入库多库位分配：独立放置子表，聚合保存

- 放置记录 `lunaerp_stock_in_item_placement`：每条入库明细可拆任意条放置（库位 + 匹数 + 数量 + 备注），库位下拉限定为入库单头所选仓库的启用库位，service 校验归属（不归属报 `1_030_011_004`）。
- 放置记录**随入库单聚合保存**（ADR-0003 模式）：整单保存时与明细一起整体替换，**无独立 Controller、无独立权限码**。这与检验单录检明细的独立子资源模式（ADR-0014）刻意不同——入库是整单装箱录入，不是多人逐卷高频并行。
- **不强制齐套**：不校验放置匹数/数量合计等于明细（前端仅显示"已分配 X / 共 Y 匹"提示）；未分配的明细审核照常过账，流水库位为空。
- 一单一仓库：主表 warehouse_id 必填；不支持跨仓分配。
- 放置记录是 ADR-0017 流水"按库位展开"的数据来源。

## 理由

1. **两级足够表达纺织贸易仓**：库位编码本身可承载行列层语义（`A-01-02`），不需要坐标几何；容量管控、平面图服务于大型立体仓/自动化仓，MVP 用户是小型纺织贸易/工厂仓，引入即用不到的复杂度正是旧系统模型沉重的来源。
2. **保留扩展位**：未来需要库区时在仓库与库位之间加一级表（location 加 zone_id 可空列），不影响入库单与流水结构；平面图画布本质是库位的可视化层，可独立后补。
3. **一条明细多库位是真实场景**：同一产品行的多匹布物理上分散存放（6 匹放 A-01、4 匹放 A-02），明细行单 location 字段无法表达；独立放置子表与旧系统 InventoryPlacement 语义一致，也让过账流水天然携带库位。
4. **不强制齐套**：业务上存在"先入账、后上架"与部分上架；强制 100% 分配会把物理上架节奏卡死在制单环节。允许库位为空的流水是刻意的宽松。
5. **聚合而非独立子资源**：放置记录的编辑入口只存在于入库工作台，生命周期完全从属于单据；独立端点只会增加权限面与并发覆盖问题，无业务收益。

## 考虑过的备选

- **完全照搬旧系统三级 + 平面图 + 坐标**：功能最全，但仅画布/库区/坐标/容量就是一整套子系统，严重超出"基本的仓库和库位"与入库 MVP 范围。否决。
- **三级（仓库/库区/库位）无画布**：库区在没有容量与平面图配套时只是一个分组字段，编码前缀即可替代。否决，未来确有需要再加表。
- **明细行加 location_id 单字段（一行一库位）**：最简，但无法表达同品种多匹分散上架，迫使仓管把一行明细拆成多行重复录入。否决。
- **放置记录做成独立子资源（ADR-0014 模式）**：适合逐卷高频并行；入库整单录入场景不成立。否决。
- **审核强制全量分配库位**：账位最严谨，但卡住未上架先入账的常态业务。否决，改为前端提示 + 允许空库位过账。

## 后果

- 本期共 6 张表：仓库、库位、入库主/明细/放置、库存流水。
- 库位编码由人工维护，仓库编号自动取号；两者唯一索引均含软删行（编号不释放）。
- 库位级库存报表、移库、库存预警均为后续模块；台账已带 location_id/location_code 快照，未来库位台账扩展无需迁移历史流水。
- 若未来库区上线，需为库位补 zone_id 可空列与"仓库管理"页的分组 UI；放置表与流水不受影响。
