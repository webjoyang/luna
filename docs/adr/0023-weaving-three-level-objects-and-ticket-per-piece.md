# ADR-0023：织造执行保留"织造单 → 机台任务 → 布票"三层对象，布票每匹一码

**状态**：Accepted
**日期**：2026-09-25
**关联**：生产管理-织造执行；ADR-0022（胚布单自织模式）、ADR-0021（挡车工复用 system User）

## 背景

参考系统织造执行的对象层级为：

```
GreigeInstruction（胚布指示单）
  └─ WeavingBatch（织造批次：一次执行计划）
       └─ MachineTask（机台任务：某台机织多少匹）
            └─ WeavingTicket（布票：每匹一码，扫码开工/完工/异常）
```

迁移到新项目时有两个简化选项：①砍掉机台任务层，布票直挂织造单，机台降为布票字段；
②布票改为每卷一码，对齐检验单现行"按卷录检"。

## 决策

**保留三层对象**，命名与粒度如下：

1. **织造单 `WeavingOrder`**（旧 WeavingBatch 正名，对齐项目 `XxxOrder` 惯例）：从 `production_mode=SELF` 的胚布单创建，一个胚布单可分 N 张织造单。
2. **机台任务 `MachineTask`**：排产动作"哪台织机织多少匹"的载体，必须保留——排产是本模块核心业务动作，且布票→任务→织造单的状态推导链依赖此层。任务字段做裁剪：保留 `planned_start/planned_end` 为普通日期，不做甘特拖拽与排产看板。
3. **布票 `WeavingTicket`：每匹一码**（一**匹**一码，票号=二维码内容），挂织造单、排产归属机台任务。

**与检验环节的衔接不通过改粒度解决**：检验单增加卷/匹双包装模式（ADR-0025），匹装检验每匹一条明细，布票粒度（匹）与检验粒度（匹）在交接路径上一致；卷装仍由检验员手工建卷装单。

## 血缘方向

布票上**不存**检验编号（旧系统 `inspectionLabelCode` 不迁移，避免预留死字段）；
录检明细上存 `weaving_ticket_id`（可空）。血缘查询方向为"布票 → 检验明细 → 检验单"，与新项目"上游 ID 存在下游单据上"的惯例一致（如入库单存合同/胚布单 ID）。

## 数量软校验

- 一个胚布单下各织造单 `plannedQty` 合计超胚布单匹数：**警告但允许**；
- 一张织造单下各机台任务 `plannedQty` 合计超织造单匹数：**警告但允许**。
交期紧、临时加单是现场常态，强校验会挡正常业务（与胚布单"计划投胚量不强制等于折算需求"哲学一致）。

## 后果

- 三层结构的代价：排产、改派、换机时需维护任务与票两级归属；通过"布票挂批次（织造单）、machine_task_id 可调"吸收。
- 每匹一码使布票行数 = 匹数，票量较大；列表需分页与按状态筛选，不做全量渲染。
- 砍机台任务层被否：没有任务层则排产无处表达，机台利用率、停机原因等业务字段失去归属。
