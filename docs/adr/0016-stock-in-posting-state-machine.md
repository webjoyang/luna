# ADR-0016：入库单三态严格过账状态机（审核=过账、取消已审核=红冲）

**状态**：Accepted
**日期**：2026-09-23
**关联**：库存管理-入库管理 MVP

## 背景

项目现有业务单据（销售合同/胚布单/染色单/纱线采购单/检验单）在 MVP 阶段的通行惯例是：状态字段存在，但编辑页可手动自由切换、后端不做严格流转约束（见检验单 spec "状态操作"章节与 ADR-0008）。

入库单与上述单据性质不同——它是**库存账的凭证**。旧系统（linaagi）入库单有 DRAFT/QC_PENDING/COMPLETED 外加审批态（PENDING_APPROVAL/REJECTED），并在生效时触发应付、订单进度、批次转可用等一串副作用，用 `effectsAppliedAt` 闸门防重复执行，模型沉重且曾因状态口径散落多处导致财务统计错误（见 `server/src/lib/stockin-scope.ts` 注释）。

新项目做入库 MVP 时必须回答：过账类单据是否沿用"自由切态"惯例？审核和取消的账目语义是什么？

## 决策

入库单采用**三态严格状态机**：

- `DRAFT` 草稿（新建缺省）：可编辑、可删除、可审核、可取消
- `COMPLETED` 已审核：**审核即在同一事务写库存流水**（ADR-0017），之后单据只读，唯一写操作是"取消"（红冲）
- `CANCELLED` 已取消：终态，只读，不可重新审核

规则：

1. 仅 DRAFT 可 create 后更新/删除；非草稿调用更新或删除报"当前状态不允许该操作"。
2. `PUT /audit`：仅 DRAFT → COMPLETED，要求至少一条明细；同事务按库位分配展开写正数 STOCK_IN 流水。
3. `PUT /cancel` 区分两种语义：
   - DRAFT → CANCELLED：仅作废单据，**不写流水**；
   - COMPLETED → CANCELLED：**红冲**，同事务按关联单号反查原流水，逐条插入负数反向行（STOCK_IN_REVERSAL），原流水永不物理删除、不可修改。
4. **制单与审核分权**：审核与红冲使用独立权限码 `lunaerp:stock:stock-in:audit`；草稿作废用 `:update`。
5. 不设 ACTIVE（入库无"执行中"语义，审核是瞬时动作）、不设 QC_PENDING（质检归检验单域）、不引入审批流。

## 理由

1. **过账不可重复**：重复过账直接意味着库存虚增，是库存模块最严重的事故类型。自由切态无法防止"COMPLETED 改完再存一次"这类路径。
2. **红冲而非删除已审核单**：已入账事实必须可审计；红冲保留原流水、追加反向行，余额自动回平，与市面主流 ERP（用友/金蝶）的作废/反审核语义一致。
3. **与现有单据惯例刻意不一致是合理的**：现有 MVP 单据（合同/胚布/染色/检验）的下游联动全部未建，状态只是标签；入库单一上线就驱动真实库存账（流水），状态即账目动作，约束强度必须匹配。
4. **分权前置**：制单与审核在系统实现期就分权限码，避免业务上线后再拆分权限模型；小团队可以两权同授一人，不增加使用负担。

## 考虑过的备选

- **沿用四态 DRAFT/ACTIVE/COMPLETED/CANCELLED + 自由切换**：与检验单/染色单同构。但 ACTIVE 对入库无业务语义（不存在"入库进行中"），且自由切态与过账安全性冲突。否决。
- **引入审批流（待审核/驳回）**：对齐旧系统。MVP 无审批引擎集成，且审批是组织流程问题，可后续在 DRAFT 与 COMPLETED 之间插入审批态，当前三态不封死该扩展路径。否决。
- **已审核单允许删除并连带删除流水**：实现最简。但销毁账目事实，审计不可接受。否决。
- **取消已审核单仅改状态、不写红冲**：余额无法回平，账实不符。否决。

## 后果

- 入库单 Service 的 update/delete/audit/cancel 全部带状态守卫与明确错误码（`1_030_011_002`、零明细 `1_030_011_005`）。
- 流水表数据只增不改不删（红冲靠追加反向行），库存余额恒等于流水 SUM。
- 前端工作台按状态渲染操作按钮，审核与红冲按钮受 `:audit` 权限控制，红冲需二次确认并提示库存影响。
- 未来如引入审批流，在 DRAFT→COMPLETED 之间增加审批态即可，三态主结构无需推翻；检验同步/采购自动入库将来创建的入库单应直接进入 DRAFT 或过账路径，不得绕过本状态机。
