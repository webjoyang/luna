# 04: 模块开通/停用端到端验证

**What to build:** 用已有的「生产」模块走通完整开通→停用→恢复链路。① 新建租户绑定核心包后登录，侧边栏可见已落地的核心模块；② 平台管理员编辑核心包取消勾选「生产」一级目录（UI 级联取消其下整棵子菜单），系统自动同步 `system_role_menu`；③ 租户用户刷新后侧边栏无「生产」，直接访问 `/production/**` 被重定向首页，调用生产 API 返回 403 且前端提示「该模块未开通，请联系管理员」；④ 将「生产」加回核心包，租户用户刷新即可见生产模块，历史业务数据完整可操作。同时确认套餐管理页菜单树级联勾选（父选子全选、父消子全消）。

> 说明：财务(10700) / 审批中心(10800) 实际菜单落地由 20-approval-engine / 26-27-29 财务模块 ticket 负责，不在本 spec 范围。「全部核心模块可见」的全量验收（含财务/审批中心）移交 32-commercialization-acceptance。本 ticket 只验证 module-gateway 自身交付物（改名 SQL、核心包 SQL、403 处理、开通/停用流程）端到端跑通。

**Blocked by:** 01（菜单改名）、02（核心包 SQL）、03（403 拦截器与路由守卫）

**Status:** ready-for-agent

- [ ] 新建租户绑定核心包后登录，侧边栏可见已落地的核心模块（基础信息 / 销售 / 生产 / 库存 / 样品 / 系统管理 / 首页）
- [ ] 从核心包移除「生产」后，租户用户侧边栏无「生产」目录及其子菜单

- [ ] 将「生产」加回核心包后，租户用户刷新即恢复生产模块，历史业务数据完整可操作
- [ ] 套餐管理页菜单树级联勾选正常：父选→子全选、父消→子全消
