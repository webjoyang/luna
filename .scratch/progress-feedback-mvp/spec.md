# 生产管理 - 进度反馈 MVP（外发染色缸级进度覆盖层 + 缸卡墙 + 反馈流水）

Status: ready-for-agent

## Problem Statement

公司把染色生产外发给外部染厂，生产过程发生在公司围墙之外：内部跟单员只能靠电话、微信向染厂询问"下单的布做到哪道工序了、什么时候能交、出了什么问题"，信息散落在聊天记录和跟单员脑子里。旧系统（linaagi，Node/Express + Prisma + React）已有进度反馈模块：按"合同+产品+颜色（+缸号）"挂接的状态覆盖层、六工序状态机、缸卡墙、反馈流水、排产覆盖率统计。但旧系统与新系统技术栈不兼容，且模型沉重（自定义工序模板、缸卡实时推送、AI 洞察、语音录入、照片视频、矩阵视图等）。

新 Luna ERP 中，业务链"销售合同 → 胚布单 → 染色单 → 检验单 → 入库单 → 发货单"已成型，但外发染色环节存在明确的进度黑盒：染色单只有 DRAFT/ACTIVE/COMPLETED/CANCELLED 四态粗粒度状态，没有缸号、工序阶段、延期标识与跟单沟通沉淀；自织织造进度已由布票体系自动解决，外发染色却没有任何跟手工具。业务侧希望先用新栈跑通进度反馈的最小可用闭环。

## Solution

在 luna-srv `lunasrv-module-lunaerp` 的 `production` 子包下新增 `progressfeedback`，落地 **2 张表**：

1. `lunaerp_production_progress_feedback` **反馈缸**：进度反馈的最小单位——某张染色单某个颜色行下投染的一缸。持有稳定关联 `dyeingOrderId` + `dyeingColorId` + `vatNo`（缸号）、本缸数量/匹数、六态状态、五个阶段日期戳、延期原因、备注。
2. `lunaerp_production_progress_feedback_note` **反馈记录**：反馈缸下的跟单沟通流水（文字内容、问题标记、闭环时间、记录人/时间），独立子资源逐行增删。

进度反馈是染色单之上的**状态覆盖层（Overlay）**，不是独立业务单据（ADR-0031）：列表以染色颜色明细行为骨架做分页投影，反馈缸经关联挂载到颜色行；没有任何反馈缸的颜色行以虚拟行"未排缸"呈现。**零展示快照**：合同号/客户/染厂/产品/颜色等展示信息不落库，全部经染色单主表与颜色行子查询实时取出。**零回写**：进度反馈不修改染色单的任何数据。

固定六工序链（字典 `lunaerp_progress_feedback_status`，id=2247）：未排缸 NOT_SCHEDULED（虚拟态）→ 已排缸 SCHEDULED（建缸缺省态）→ 染色中 DYEING → 固色中 FIXING → 质检中 QUALITY_CHECK → 已完成 COMPLETED。推进逐格前进、后端自动盖当天日期戳；日期可修正、状态可回退（二次确认）；无取消态，录错的缸直接删除。

前端在 `views/lunaerp-elmui/production/progress-feedback/` 落地**缸卡墙**桌面版（Vue3 + Element Plus：颜色行分节卡片 + 缸卡网格 + 统计条 + 筛选 + 建缸/推进/反馈弹窗 + 缸详情抽屉），并在染色单工作台加只读"进度反馈"页签作为第二入口。配套 PostgreSQL 脚本完成 2 表 DDL、菜单 10400 及 10401-10405 按钮权限、1 个字典初始化。

**硬前置**：染色颜色行 id 的稳定性由阶段一（`.scratch/aggregate-differential-save/spec.md`，ADR-0032）保证，阶段二必须在阶段一合并后开工。

## User Stories

### 缸卡墙列表与骨架投影

1. 作为跟单员，我想在"生产管理 → 进度反馈"菜单看到缸卡墙：以染色颜色明细行为骨架逐行分节，每一节展示合同号、客户、染厂、产品、颜色（客户色号 + 颜色名称）、颜色行染色数量/匹数/单位，以便按下单原貌逐色跟进。
2. 作为跟单员，我想骨架只取 ACTIVE（进行中）与 COMPLETED（已完成）染色单的颜色行；DRAFT 草稿（尚未下达给染厂）与 CANCELLED 已取消染色单的颜色行不进入覆盖层。
3. 作为跟单员，我想每个颜色行节内以卡片网格展示其下全部反馈缸：缸号、本缸数量/匹数、当前状态标签、步骤进度指示、未决问题红点，以便一屏看清这色布分了几缸、各到哪一步。
4. 作为跟单员，我想零反馈缸的颜色行显示一张虚线"＋ 建缸"占位卡（虚拟未排缸行），以便一眼看出哪些颜色完全还没排缸并直接开建。
5. 作为跟单员，我想颜色行节头展示排产覆盖率：已建缸数量合计、颜色行染色数量、覆盖率百分比；已建缸合计超过颜色行染色数量时百分比红色预警但不阻止操作（临时加缸是常态）。
6. 作为跟单员，我想覆盖层列表以颜色行为骨架分页（每页固定数量颜色行），其下缸卡随节一起加载，避免一次性拉全量数据。
7. 作为跟单员，我想一个颜色行下各缸的单位跟随颜色行单位（KG/M）展示，数量口径一致。

### 统计条

8. 作为跟单员，我想列表顶部看到统计条：未排缸颜色行数、进行中缸数（已排缸/染色中/固色中/质检中合计或分列）、已完成缸数、延期缸数，以便全局掌握车间跟单压力。
9. 作为生产主管，我想点击统计条某个计数能快速筛选到对应范围（如只看延期缸），统计口径与当前筛选条件联动。

### 筛选与检索

10. 作为跟单员，我想按染色单筛选（远程搜索/下拉选择），以便聚焦某一张单。
11. 作为跟单员，我想按销售合同号关键词筛选，以便从合同维度找进度。
12. 作为跟单员，我想按染厂（承染方供应商）筛选，以便按染厂分片跟催。
13. 作为跟单员，我想用一个关键词同时匹配颜色名称、客户色号与缸号，以便只记得缸号也能定位。
14. 作为跟单员，我想按进度状态筛选（未排缸/已排缸/染色中/固色中/质检中/已完成），以便聚焦特定工序。
15. 作为跟单员，我想一键"仅看延期"，只列出过了交期仍未完成的缸。
16. 作为跟单员，我想一键"仅看未决问题"，只列出存在未闭环问题记录的缸。
17. 作为跟单员，我想用开关切换"含已完成颜色行"（默认隐藏全部缸已完成的颜色行，进行中视图优先）。
18. 作为跟单员，我想有"含已失效"开关：染色单被删除（软删）后其反馈缸默认隐藏，打开后可查看这些残留缸记录。
19. 作为跟单员，我想筛选条件同时作用于骨架分页与统计条计数，结果一致。
20. 作为跟单员，我想缸卡墙上提供类似参考系统的物料单元快速定位条（按染色单/合同+产品聚合的快捷入口），点击后与筛选条件双向同步，定位后直接滚动到对应颜色行节。

### 建缸

21. 作为跟单员，我想在颜色行节点"＋ 建缸"（或占位卡）打开建缸弹窗：染色单与颜色行已由入口确定，只需填缸号、本缸数量（必填 >0）、匹数（可空）、备注（可空）。
22. 作为跟单员，我想缸号是自由文本（兼容染厂自己的缸号格式），必填；同一染色单同一颜色行下缸号不可重复，重复时后端报错（1-030-017-001），由我修改。
23. 作为跟单员，我想建缸提交后新缸状态为 SCHEDULED 已排缸，排缸日（第一个阶段日期戳）缺省盖为提交当天，可在弹窗中改成实际排缸日期。
24. 作为跟单员，我想只能对 ACTIVE/COMPLETED 染色单的颜色行建缸；对 DRAFT/CANCELLED 单或不存在的颜色行建缸时后端报错（1-030-017-002 / 003）。
25. 作为跟单员，我想建缸时弹窗展示该颜色行的染色数量与当前已建缸合计/覆盖率，并在本缸数量导致超排时给红色软警告（允许继续保存）。
26. 作为跟单员，我想建缸不需要业务单号（同染色单先例），缸靠"染色单+颜色+缸号"识别。
27. 作为跟单员，我想在独立菜单页建缸时先选染色单（只列 ACTIVE/COMPLETED）、再选该单颜色行，表单联动；在染色单页签建缸时这两步自动带入。

### 状态推进与阶段日期

28. 作为跟单员，我想在缸卡上点"推进"把缸从当前工序推进到下一工序（已排缸→染色中→固色中→质检中→已完成），后端在同一次操作写入新阶段的当天日期戳，不允许跳格。
29. 作为跟单员，我想推进到最后一格后缸卡显示完成态，卡片上五个阶段日期（排缸日/染色开始/固色开始/质检日/完成日）齐全。
30. 作为跟单员，我想在缸详情中看到六工序时间轴：每道工序名称与对应日期戳（未到达的工序为空态），当前工序高亮。
31. 作为跟单员，我想录错时能在缸详情编辑各阶段日期，并能把状态回退到上一工序；回退操作弹窗二次确认，确认后更新状态（回退不强制清除已盖日期戳，日期以人工修正为准）。
32. 作为跟单员，我想对已完成（COMPLETED）缸仍可修正日期与备注（内部跟单记录，非过账凭证，不设严格终态锁），但推进按钮在 COMPLETED 态消失。
33. 作为跟单员，我想缸信息（缸号、数量、匹数、延期原因、备注）可在缸详情中编辑保存，受 `:update` 权限控制；推进动作独立受 `:advance` 权限控制。

### 延期

34. 作为跟单员，我想缸的交期自动取所属染色单的交货日期，不需要在反馈缸上重复录入交期。
35. 作为跟单员，我想当前日期晚于交期且缸状态不是已完成时，缸卡与详情用红色延期标记，并计入统计条延期数。
36. 作为跟单员，我想能在缸上登记延期原因（自由文本，可空可改），以便记录染厂解释（等料/设备/返工等），交期变更后延期标记按新交期自动重新判定。
37. 作为跟单员，我不想看到"单工序滞留 12 小时"之类的自动预警（本期不做工序滞留预警）。

### 反馈记录（沟通流水）

38. 作为跟单员，我想在缸卡上点"反馈"（或缸详情的反馈记录区）快速新增一条反馈记录：文字内容必填、可勾选"这是问题"，提交后记录立刻出现在该缸时间线，记录人与时间由系统自动写入。
39. 作为跟单员，我想在缸详情抽屉看到该缸全部反馈记录的时间线（时间、记录人、内容、问题标记、闭环状态），最新在前或在后有一致排序，以便复盘"这缸都发生过什么"。
40. 作为跟单员，我想反馈记录只能新增和删除、不能修改正文（流水留痕）。
41. 作为跟单员，我想把标记为问题的记录点"闭环"，系统记录闭环时间；缸卡上未闭环问题数以红点显示，全部闭环后红点消失。
42. 作为跟单员，我想已闭环的问题记录不能删除（1-030-017-101），也不能重复闭环；普通（非问题）记录可删除。
43. 作为跟单员，我想删除反馈缸时其下全部反馈记录级联逻辑删除；反馈记录的新增/删除/闭环统一受 `:note` 权限控制。
44. 作为跟单员，我想本期反馈记录只支持文字，不上传照片/视频/语音（现场信息先文字承载）。

### 删除缸

45. 作为跟单员，我想录错缸时可以删除该反馈缸（任意状态可删，二次确认），删除后颜色行的已建缸合计与覆盖率立即重算，若该颜色行零缸则恢复虚拟未排缸占位卡。
46. 作为跟单员，我想删缸只影响覆盖层数据，染色单与颜色行不受任何影响，染色单侧零感知。
47. 作为跟单员，我想删缸操作受独立 `:delete` 权限控制，无权限时按钮不显示/置灰。

### 第二入口：染色单工作台页签

48. 作为跟单员，我想在染色单整页编辑页看到"进度反馈"页签：只读展示该单全部颜色行的缸卡墙（同组件复用），并能直接建缸、推进、写反馈，不必跳到独立菜单再筛选一遍。
49. 作为跟单员，我想染色单页签上的进度操作与独立菜单走完全相同的接口与权限校验；染色单保存动作与进度反馈数据互不影响。
50. 作为业务员，我想在编辑染色单移除某个颜色行时，如果该颜色行下存在反馈缸，后端硬拦截报错并提示"颜色【X】下有 N 条缸进度反馈，请先删除后再移除该颜色行"（1-030-017-004），而不是保存成功后让反馈缸变孤儿。

### 权限、菜单与数据规范

51. 作为管理员，我想"进度反馈"挂在生产管理目录下（菜单 id 10400），含五个按钮权限（10401 建缸 create / 10402 编辑 update / 10403 推进 advance / 10404 删除 delete / 10405 反馈记录 note），查询权限由菜单承载，以便按角色分权（如跟单员可全部操作、主管只读）。
52. 作为管理员，我想权限码统一为 `lunaerp:production:progress-feedback:` 前缀；反馈记录作为独立子资源其端点也挂同一套菜单授权（不另开菜单）。
53. 作为开发者，我想两张新表继承项目审计/多租户/软删除基类惯例，逻辑关联（dyeing_order_id、dyeing_color_id、vat 主表 id）不建数据库外键；缸号重复只在 service 层校验，不建数据库唯一约束。
54. 作为开发者，我想反馈缸表上不存在合同号/客户名/染厂名/产品名/颜色名等任何展示快照列；列表查询通过染色单主表与颜色行关联实时取这些字段。
55. 作为开发者，我想所有列表/详情接口返回延期标记、覆盖率、未决问题数这类派生字段时由后端计算（前端不做业务计算，同项目测算口径惯例）。
56. 作为开发者，我想建缸/推进/反馈的写操作被框架操作日志或标准审计字段记录创建人与时间，沿用项目通用机制即可，不另建操作日志表。

## Implementation Decisions

- **后端落点**：`com.luna.lunasrv.module.lunaerp.{controller,service,dal}.production.progressfeedback`，反馈记录子资源在其下 `.note`（或 `.note` 子包），仿检验录检明细 ADR-0014 的独立子资源组织。
- **表结构（2 表，SQL 文件 `luna-srv/sql/postgresql/lunaerp-production-progress-feedback.sql`）**：
  - `lunaerp_production_progress_feedback`：框架审计列（tenant_id、creator/create_time/updater/update_time/deleted）+ dyeing_order_id、dyeing_color_id（逻辑关联，无外键）、vat_no、quantity（numeric）、pieces（int 可空）、status（六态字符串）、scheduled_date、dyeing_started_date（染色开始）、fixing_started_date（固色开始）、quality_check_date、completed_date（五个日期戳均可空可人工修正）、delay_reason、remark。索引按 (tenant_id, dyeing_order_id, dyeing_color_id) 与状态列建普通索引；**不建**名称快照列、**不建**数据库唯一约束。
  - `lunaerp_production_progress_feedback_note`：框架审计列 + feedback_id、content（非空文本）、issue_flag（boolean）、resolved_at（可空）、resolver 可由审计列承载。流水只增不改。
- **状态机**：`SCHEDULED→DYEING→FIXING→QUALITY_CHECK→COMPLETED` 严格顺序（NOT_SCHEDULED 仅虚拟态不入库）。advance 接口：校验当前态有后继、写入目标态与对应阶段当天日期；update 接口允许改全部阶段日期与回退状态（回退前端二次确认，后端不拦回退但记录 updater）。
- **覆盖层查询（核心读模型）**：以染色颜色明细分页为骨架（join 染色单主表，过滤单状态 ACTIVE/COMPLETED + 租户 + deleted=0；染色单软删时默认排除、"含已失效"放开），每节 LEFT JOIN 聚合其下反馈缸（含状态分组计数、数量合计、未决问题计数），并实时带出染色单快照列（contract_no/client_name/dyeing_factory_name）与颜色行字段（customer_color_no/color_name/quantity/pieces/单位）。延期标记 = 染色单交货日期 < 今天 且 缸 status ≠ COMPLETED。覆盖率 = Σ缸数量 ÷ 颜色行 quantity（零/空分母按 0% 处理），超排标记 = Σ缸数量 > 颜色行 quantity。骨架筛选项（合同号/染厂/状态/延期/未决问题/含已完成/含已失效）下推到颜色行查询；统计条在同一过滤口径上计数（未排缸颜色行数 = 零缸节数）。
- **API 契约（前缀 `/lunaerp/production/progress-feedback`，统一 CommonResult 包装与分页对象）**：
  - `GET /page`：覆盖层骨架分页（颜色行节 + 节内缸 + 派生字段），入参为分页 + 全套筛选；
  - `GET /list-by-order?id={dyeingOrderId}`：染色单页签用，返回该单全部颜色行节（无分页或大页容）；
  - `GET /statistics`：统计条计数（同筛选口径）；
  - `GET /{id}`：缸详情（缸字段 + 五阶段日期 + 颜色行/染色单实时信息 + 延期/覆盖率）；
  - `POST /`：建缸（入参 dyeingOrderId、dyeingColorId、vatNo、quantity、pieces、scheduledDate 可空、remark；校验单状态/颜色行归属/缸号重复/数量>0；状态置 SCHEDULED）；
  - `PUT /`：编辑缸信息与阶段日期、状态回退；
  - `POST /advance`（或 `PUT /advance`）：推进；
  - `DELETE /{id}`：删缸（级联软删记录）。
  - 反馈记录 `/progress-feedback-note`：`GET /list-by-feedback?feedbackId=`、`POST /`（新增，可带 issueFlag）、`POST /resolve`（问题闭环）、`DELETE /{id}`（闭环问题禁删）。
- **错误码段 `1-030-017-xxx`**：000 反馈缸不存在 / 001 同单同色缸号重复 / 002 染色单不存在或状态不允许建缸 / 003 染色颜色行不存在 / 004 颜色行下存在反馈缸不能移除（染色单更新守卫跨模块调用）/ 100 反馈记录不存在 / 101 问题已闭环不可操作。
- **菜单/权限/字典 SQL**：system_menu 10400（目录 10200 下，component 指向 lunaerp-elmui/production/progress-feedback/index）+ 10401-10405 按钮位，SQL 注释写明跳号原因（10290-10298 织造领纱已占、10300+ 库存目录已占）；字典 type `lunaerp_progress_feedback_status`（id=2247）含六态（NOT_SCHEDULED 作为虚拟态也入字典用于渲染，但后端不持久化该值）；单位复用 `lunaerp_sales_contract_unit`。
- **前端结构**：
  - `views/lunaerp-elmui/production/progress-feedback/index.vue`（缸卡墙页：统计条 + 筛选栏 + 单元定位条 + 颜色行节列表分页）；
  - 组件：`VatCard.vue`（缸卡：状态标签、el-steps/el-progress 工序指示、问题红点、推进/反馈/删除操作按权限显隐）、`ColorSection.vue`（节头 + 覆盖率 + 缸卡网格 + 虚线建缸占位卡）、`VatCreateDialog.vue`、`VatAdvanceDialog.vue`、`FeedbackDialog.vue`（新增反馈）、`VatDetailDrawer.vue`（六工序时间轴 + 缸信息编辑 + 反馈记录时间线 + 闭环）；
  - `api/lunaerp-elmui/production/progress-feedback/index.ts` 与 note API；
  - 染色单工作台加 `ProgressFeedbackTab.vue`（复用 ColorSection 系列组件，调 list-by-order）。
  - 视觉用 Element Plus 组件 + scoped SCSS 实现桌面宽屏（缸卡 grid auto-fill），不引参考系统的 Tailwind/framer-motion；状态颜色与 DictTag 一致。
- **跨模块改动（仅两处，均零回写）**：① DyeingOrderServiceImpl 更新流程中启用阶段一预留的反馈缸守卫（差异保存得出待删颜色行 id → 查反馈缸存在性 → 抛 1-030-017-004）；② 染色单工作台前端加页签。染色单 DO/表结构/状态机/接口均不改。

## Testing Decisions

- **唯一测试接缝**：ServiceImpl 层 Mockito 单测（不起 Spring、不连库），沿用 ShipmentServiceImplTest / InspectionOrderItemServiceImplTest 标杆，不新增测试类型。
- **新增两个测试类**：
  - `ProgressFeedbackServiceImplTest`：建缸（成功缺省 SCHEDULED + 排缸日缺省当天/传入日期优先；缸号重复抛 001；非 ACTIVE/COMPLETED 单抛 002；颜色行不存在或不属于该单抛 003；数量非法拦截）；推进（逐格成功且对应日期戳被写入；跳格/COMPLETED 再推进被拒）；编辑与回退（日期修正、状态回退放行）；删除（级联软删记录调用、任意状态可删）；覆盖层分页组装（节骨架状态过滤、零缸节虚拟未排缸、LEFT JOIN 挂载、染色单软删默认排除/含已失效放开）；延期判定（交期前后与 COMPLETED 三种情形）；覆盖率与超排（正常/超排/零缸/零分母）；统计条计数口径。
  - `ProgressNoteServiceImplTest`：新增（普通/问题两种、记录人时间注入）、列表排序、闭环（成功写 resolvedAt；重复闭环拒；非问题记录闭环拒或按设计忽略——以接口语义为准）、删除（普通记录可删；闭环问题抛 101；不存在抛 100）；删缸级联由主表测试覆盖。
- **跨模块守卫用例**：DyeingOrderServiceImplTest 增加用例——待删颜色行存在反馈缸时抛 1-030-017-004、无反馈缸时正常差异保存（mock progressVatMapper 协作者）。
- **好测试标准**：只断言外部行为（返回 DTO 的节/缸/派生字段、状态与日期落库值、抛出的错误码、对 Mapper 的可观察写操作），不断言 SQL 片段与私有方法；Mapper 全部 mock；日期相关逻辑通过可注入时钟/固定当天日期断言（沿用项目现有时间处理手法）。
- **前端无自动化测试**（仓库无前端测试设施）：人工回归清单验收——骨架与筛选/统计口径一致、建缸/推进/反馈/闭环/删除全链路、覆盖率与延期红绿标记、染色单页签与独立菜单数据一致、权限按钮显隐、染色单删行守卫提示文案。

## Out of Scope

- 外发胚布（坯布厂织造）进度跟踪、全链路合同→发货进度看板。
- 染厂外部账号/供应商门户、移动端/H5、消息通知与催办。
- 照片/视频/附件上传、语音录入、AI 洞察/摘要、实时推送（WebSocket/SSE）。
- 自定义工序模板与工序组合器、矩阵分列视图、单工序滞留时长预警。
- 投入量/成品回产量/损耗率统计、排产自动调度、覆盖率驱动的库存联动。
- 对染色单的任何回写（状态、数量、交期均不动）；反馈缸业务编号；审批流。
- 阶段一的聚合差异保存改造（见 `.scratch/aggregate-differential-save/spec.md`），但阶段二开工前必须先合并阶段一。

## Further Notes

- 领域术语与边界以 CONTEXT.md「生产管理：进度反馈」节为准；架构取舍见 ADR-0031，前置机制见 ADR-0032，反馈记录独立子资源模式见 ADR-0014，无编号先例见 ADR-0009。
- 实施顺序建议：① SQL（2 表 + 菜单 + 字典）；② DO/Mapper + 覆盖层读模型查询与分页；③ 反馈缸 CRUD/推进/删除 + 单测；④ 反馈记录子资源 + 单测；⑤ 启用染色单删除守卫；⑥ 前端缸卡墙与弹窗/抽屉；⑦ 染色单页签；⑧ 人工回归。
- 覆盖层查询是本功能实现风险最高处（骨架分页 + 节内聚合 + 多筛选下推），实现时优先保证"骨架颜色行数分页正确、筛选与统计同口径"，再优化查询形态。
- 参考实现位于旧系统 `linaagi` 的 server `progress-feedback*` 服务/路由与 web `staff/components/progress-feedback/`，仅作信息架构参照，代码不移植。
