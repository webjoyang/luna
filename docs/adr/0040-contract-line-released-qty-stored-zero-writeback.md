# ADR-0040：合同行已下达量落库累加、下游单据修改/删除零回写

**状态**：Accepted
**日期**：2026-10-07
**关联**：合同「下达生产」工作台（release-production）；ADR-0034（生产进度只读聚合）、ADR-0003（合同明细聚合保存）、ADR-0022（胚布单自织模式）；对照 shipment `from-contract` 实时未发量

## 背景

合同→生产唯一入口（charting Q7=A）需要回答两个问题：① 如何知道某合同行还能下达多少生产（部分下达/追加下达/超下达拦截）；② 下游生产单据（胚布/染色/检验）生成后，若被独立修改数量或删除，合同行的"已下达量"是否同步。

对照方案是发货模块的 `from-contract`：未发量 = 合同数量 − 已生效出库数量，**实时聚合不落库**。但生产场景与发货不同：下游单据是长期在途的执行指令（非一次性出库凭证），且合同行需要聚合查询生产进度（issue 08 第 3 条），每次实时反查多表性能与口径成本更高。

## 决策

### 1. 合同行加 `released_qty`，下达时同事务累加

`lunaerp_business_sales_contract_item` 新增 `released_qty numeric(18,2) NOT NULL DEFAULT 0`。下达生产时，在创建下游单据的同一事务内：

```sql
UPDATE lunaerp_business_sales_contract_item
SET released_qty = released_qty + #{delta}
WHERE id = #{contractLineId}
  AND tenant_id = #{tenantId}
  AND released_qty + #{delta} <= quantity   -- 超下达拦截
```

影响行数 0 即并发/超下达，抛错误码。剩余可下达量 = `quantity − released_qty`，读合同行即可，无需实时反查。

### 2. 下游单据修改/删除不回写 `released_qty`

四类生产单据（胚布/染色/检验/打色）是**独立聚合根**（Q7=A，不建聚合实体），生成后可在各自页面独立修改数量、颜色乃至删除。这些动作**不回写**合同行 `released_qty`：

- 已下达是既成事实，单据后续变更不改变"曾经下达过"这一事实；
- 回写会引入跨聚合根的双向耦合，破坏生产进度聚合（ADR-0034）的零回写边界；
- 若需精确管控（如删除已下达单后释放额度），二期加重算任务或在单据删除时校验，不在一期范围内。

### 3. 合同行变更不影响已下达单据

合同行数量/颜色变更（合同编辑）只约束**未来**下达：若变更导致 `released_qty > 新 quantity`，提示差异但不自动回滚已下达单据、不强制纠正（零回写惯例）。合同行一旦有下达记录（`released_qty > 0`）仍可编辑，但下达服务按新 `quantity` 做超下达校验。

## 后果

- **正面**：合同行进度聚合（已下达量/剩余量）读单字段即可，性能与口径稳定；超下达拦截天然幂等（条件更新影响行数 0）；四类单据保持完全独立，无跨根回写耦合。
- **代价**：`released_qty` 是"下达时刻"的快照，不反映下游单据后续的数量变更或删除；若用户删除一张已下达的胚布单，`released_qty` 不会减少，可能出现"已下达量 > 实际在途量"。这是刻意接受的口径偏差——以"下达事实"为准，不以"在途现状"为准，与生产进度聚合（ADR-0034）的"只读投影"定位互补（进度聚合反映在途现状，`released_qty` 反映下达历史）。
- **二期路径**：若业务要求精确管控，可在下游单据删除时加守卫（已下达单删除需走"撤销下达"流程并扣减 `released_qty`），或定时重算任务对账；不影响一期 schema。
