# ADR-0044：客户门户免登模型——令牌即身份，单令牌轮换，app-api 前缀隔离

**状态**：Accepted
**日期**：2026-10-07
**关联**：wayfinder 14-customer-portal grilling（Q2/Q3/Q6/Q7）；ADR-0037（域/横切包结构）；spec `.scratch/customer-portal/spec.md`；前置契约 04 号（`luna.portal.base-url`、二维码 URL）、10 号（对账单门户 4 端点）、20 号（出口单证二期页）

## 背景

商业化 W4 要给外部客户提供免登录 H5 门户（查发货单并签收、查对账单并确认）。luna-srv 基于 yudao 底座，鉴权体系只有"管理端员工"（`/admin-api` + 账号密码/SSO 登录）；客户不是员工，没有可复用的登录身份。免登需要回答三个问题：客户凭什么进入（凭证形态）、凭证绑定什么（身份粒度）、门户端点挂在哪个鉴权域（边界）。

三条已查清的事实：

1. 底座天然存在 `/admin-api`（管理鉴权）与 `/app-api`（会员端）两个前缀，security 对 `@PermitAll` 注解端点豁免登录校验；本仓库没有任何已迁移的会员（member）体系可复用。
2. 04/10 号打印二维码契约已冻结为**无凭证的页面 URL**（`/portal/shipment?no=`、`/portal/statement?no=`）——印在纸上的链接不能携带可轮换凭证，二维码 URL 与登录凭证是两个正交问题。
3. 10 号对账单确认已按"确认人=手填姓名（confirm_by_name）"落契约，shipment 签收同理（signedByName 手填字段现成）；业务上从未要求区分客户内部哪个人操作。

## 决策

1. **令牌即身份**：门户不建模"门户用户"。免登令牌直接绑定 `{tenantId, customerId}`，校验通过即注入该客户上下文；签收人/对账确认人由客户页面手填姓名回传，审计粒度=客户+手填姓名。
2. **单令牌轮换**：每客户同一时刻仅一枚有效令牌；重新生成即吊销旧令牌（Redis 反向索引定位旧键），支持手动吊销。链接=客户门户钥匙，语义唯一。
3. **URL 令牌即 API 凭证，不换发**：`?t=` 进入后前端持久化、每请求以 `X-Portal-Token` 头携带；不做"短时 code 换会话"双键兑换。令牌 128bit 随机（Base64URL 43 字符）不可枚举，30 天滑动过期。
4. **app-api 前缀隔离**：门户端点统一 `/app-api/lunaerp/portal/**`，`@PermitAll` 豁免 admin 鉴权，自研 `PortalTokenFilter` 完成校验/续期/限流/上下文注入；10 号冻结的 `/portal/finance/statement/` 作为模块内相对前缀不变。管理端签发接口走 `/admin-api` + 芋道权限码，两端零交叉。

## 理由

1. **最小身份面**：一期门户只做"看自己的单据+两个确认动作"，不区分操作人、不存密码、不管找回——引入 portal_user 表会连带账号生命周期、找回、停用一串复杂度，而业务签收栏本来就是手填姓名。外部身份面越小，越权面越小。
2. **单令牌语义清晰**：多令牌并存（发不同联系人）看似灵活，实际带来"吊销哪枚、审计算谁、剩余有效期看哪枚"的管理负担；重发即轮换与线下"把新链接发给客户"的动作天然对齐。
3. **不换发的代价可接受**：URL 令牌可能经浏览器历史/聊天记录扩散，但其 128bit 熵不可枚举、可随时吊销重发、TTL 30 天兜底；双 token 兑换防的是"URL 泄露后长期可用"，单令牌轮换已覆盖该风险的主要路径，一期不值得多一次往返与双键状态机。
4. **app-api 边界硬**：靠 `/admin-api` + @PermitAll 白名单做免登会让"免登录的管理端点"与真实 admin 端点混在同一前缀下，审计与网关规则难收敛；app-api 前缀让门户端点在 URL 层面即可被网关/日志/限流整体识别，`@PermitAll` 收敛在 portal 包内可全局审计。

## 考虑过的备选

- **手机号+短信验证码登录**：体验正规，但私有化买断客户需自购短信通道，签发链路引入外部依赖；一期否决（线下发链接零依赖）。
- **portal_user 客户联系人账号表**：可审计到人、可按联系人停用，二期若客户要求区分操作人再立项；一期以"手填姓名+客户粒度审计"替代。
- **双 token 兑换（code 换 session）**：语义更"正规"，但多一次往返、多一套过期参数，收益（防 URL 泄露长期可用）已被轮换+吊销+TTL 覆盖。否决。
- **挂在 `/admin-api` + @PermitAll**：实现最省，但边界模糊、审计面混杂。否决。

## 后果

- 门户令牌全存 Redis（主键+反向索引双键），**零新表**；Redis 丢失=全部门户链接失效，重新生成即可，无数据损失。
- 客户侧审计只能到"客户+手填姓名"，签名栏无系统强制实名；合同/对账单的法律效力依赖线下签章流程，门户确认仅作业务凭证。
- 15 号车间移动 H5 复用"免登路由区+独立 axios+横切凭证 Filter"的工程模式，但凭证机制不同（员工账号体系），两票共享模式不共享令牌。
- 二期若引入门户用户体系，令牌改绑 userId、增加登录/找回页面即可，端点与前端路由结构不变；`?no=` 二维码契约不受影响。
