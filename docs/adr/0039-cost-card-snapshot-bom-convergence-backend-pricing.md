# ADR-0039：成本卡快照模型、配比源收敛 BOM 与后端算价权威性

**状态**：Accepted
**日期**：2026-10-07
**关联**：W1 售前链成本卡与智能报价（`.scratch/cost-card-quotation/spec.md`）；ADR-0011（配比独立 yarn_recipe_bom 表）、ADR-0035（产品信息对齐与纱线成本计算迁移）、ADR-0004（编号全量唯一含软删）、ADR-0038（回收站边界）

## 背景

售前链需要"纱价→成本卡→报价单→销售合同"的定价闭环。设计时发现三处既有张力：

1. **配比双轨**：ADR-0011 确立 `lunaerp_production_yarn_recipe_bom(+item)` 为纱线配比唯一权威源（结构化、强关联纱线档案、胚布单测算在用），但 BOM 行只有材质/规格/比例/纺法/ref_price；ADR-0035 随后在产品档案 `yarn_specs` JSON 行上落地了字段最全的三模式成本计算（损耗率/经纬方向/密度/织缩率/每米用量），且算价纯函数只在**前端**（`product-yarn-cost.ts`）。两个数据源、两套算价路径并存。
2. **成本无时点语义**：产品档案上的加工费/成本字段原地更新，老系统 QuotationItem 只存一个 costPrice 快照数字，回答不了"这张报价按哪版纱价、哪版工费算的"；染色/定型/检验/运费六项工缴费在新栈完全无处维护。
3. **金额不可测**：统一 DoD 要求金额逻辑必有测试、服务端权威重算（销售合同 ADR-0003 已立此先例），而纱线成本权威实现当时只存在于前端 TS，服务端无算价、无金额测试接缝。

## 决策

1. **成本卡是独立单据而非产品字段**：`lunaerp_business_cost_card`（+结构化纱线行/费用行子表）落 business 域，状态机 DRAFT/EFFECTIVE/EXPIRED，同一产品同时仅一张 EFFECTIVE（部分唯一索引兜底），生效即冻结；调价走"复制新建→重新取价→生效"，新生效同事务顶旧卡为 EXPIRED。卡头保留产品规格快照与双口径（KG/METER）不含税/含税四个单位成本。
2. **报价快照成本卡摘要**：报价行存 `cost_snapshot` JSON（卡号/取价日期/双口径成本/纱线与费用明细冗余）+ 成本单价列；卡后续失效或复制改版不影响历史报价自解释。允许无卡时由有权限者手工填成本（cost_source=MANUAL）。
3. **配比源收敛到 BOM**：`yarn_recipe_bom_item` 补齐 waste_rate/direction/density/crimp_rate/consumption_kg_per_meter 五列，成为成本卡、胚布单测算、产品成本分区的共同上游；产品档案 `yarn_specs` JSON 维持 ADR-0011 的废弃结论（列保留不删、不写入）。
4. **算价权威在后端**：三模式公式移植为 Java 纯函数 `CostCardPricingCalculator`（BigDecimal、4 位小数 HALF_UP、损耗钳制规则与 TS 一致），并开放不落库 `/trial` 试算接口；产品成本分区与成本卡编辑页都调后端。前端 `product-yarn-cost.ts` 及其单测**保留**作公式参考与迁移对照，但加注释声明不再是权威路径。本点是对 ADR-0035 D5"前端迁移算价"的显式修订——ADR-0035 的字段迁移（D1–D4、D6–D7）仍然有效。
5. **纱价独立主档**：`lunaerp_production_yarn_price`（规格+价类 PURCHASE/MARKET+生效日期+历史）落生产域，取价=不晚于当日的最近一条，无记录回退 `yarn_spec.ref_price` 并标记来源；维护入口挂纱线档案抽屉，不设一级菜单。
6. **报价单同号多版本**：`(quotation_no, version_no)` 全量唯一含软删，修订=旧 CONFIRMED 同事务置 SUPERSEDED + 同号 version+1 新 DRAFT（部分唯一索引保证同号至多一草稿）；"已失效"是有效期派生标记不落状态。
7. **毛利采用真毛利率口径**：`报价=成本/(1−毛利率)`、反算 `1−成本/报价`，刻意不沿用老系统 `成本×(1+加成率)` 公式，以与 W3 经营账毛利口径一致。

## 理由

1. **为什么独立卡而不是扩充产品成本字段**：纱价与工缴费随时间波动，报价与未来的经营分析必须追溯定价时点；产品档案原地改无历史、无状态、无法回答"同产品两张报价为何成本不同"。独立卡 + 同品一生效 + 生效冻结，用最小状态机换完整时点轨迹。
2. **为什么快照进报价而不是实时 join 卡**：报价是对外承诺，成本底牌在报价发出后必须固化；卡会被顶失效、价格会变，实时引用会让历史报价的毛利数字漂移。快照使报价单在任何后续主数据变化下自解释，卡表只承担"当前标准成本"职责。
3. **为什么收敛双轨**：JSON 文本行无法 join 纱价表、无法做"某规格涨价影响哪些产品/卡"的反查，且前后端各算一套必然漂移；BOM 本就是 ADR-0011 指定的权威源，补齐五列比长期维护双源便宜。借成本卡偿还双轨债，避免胚布单、成本卡、产品页三个消费者各接一套。
4. **为什么算价必须在后端**：金额权威在服务端是本栈既定模式（合同行金额忽略前端汇总）；后端纯函数可做边界全覆盖单测（空数组/全零/损耗钳制/经纬分组/双口径换算/含税），前端试算只是同一接口的实时投影；也为后续审批、经营账复用同一算价口径铺路。
5. **为什么不建工序费用主档/不自动回写采购价**：一期客户量小，染费/工缴一厂一价、一单一议，主档维护成本高于复用收益；采购实际价含税运批次差异大，自动回写会污染标准成本。两者都留了结构化入口（费用行可扩充字典、价格 source 枚举预留 PURCHASE_AGG），二期可平滑升级。
6. **为什么"已失效"不落状态**：有效期是时间谓词，落状态需要定时任务或懒迁移，valid_to 一改还得回滚状态，是状态机反模式；派生徽章 + 转合同软警告覆盖全部业务需要。

## 考虑过的备选

- **不建成本卡实体，扩充产品档案成本分区（一产品一份、改了覆盖）**：无时点轨迹、无生效替换流程、报价毛利不可追溯。否决。
- **成本卡直接消费产品 yarnSpecs JSON，维持双轨**：字段现成零迁移，但后端无法 join 纱价、无法反查影响面，且与 ADR-0011 权威源裁定冲突。否决。
- **算价继续只在前端，服务端只存结果**：金额无测试接缝、客户端可绕算直写、与合同权威重算模式不一致。否决。
- **纱价只在 yarn_spec 加采购价/市场价/生效日期三列不留历史**：取价时点与成本卡版本化无数据支撑，涨价后无法解释成本变动。否决。
- **报价每次修订生成独立新单号**：对外沟通断裂（客户认同一编号的多版方案），且无法表达"v2 替代 v1"。否决。
- **沿用老系统成本加成公式**：15% 档与真毛利率差 2.6 个点、30% 档差近 7 个点，W3 经营账口径会与报价对不上。否决。
- **一期建工序费用主档/核价申请流/报价审批**：皆为真实价值但超出 W1 最小闭环，列入二期（spec Out of Scope 已登记）。

## 后果

- 新增 6 张表（纱价 1 + 成本卡 3 + 报价 2）与 3 处 ALTER（BOM 行 5 列、客户默认毛利率、合同报价来源 2 列）；错误码 1-030-034（成本卡/报价；032 打色指示单、033 出口单证已占）与 1-030-008 追加（纱价 008/009）。
- 前端产品成本分区改调 `/cost-card/trial`；BOM 管理页补 5 列维护；`product-yarn-cost.ts` 冻结保留。
- 新增术语进 business/production/baseinfo 三域 GLOSSARY；报价打印件白诺不含成本/毛利字段。
- 成本卡/报价不产生库存与经营账副作用，W3 经营账的毛利分析以报价/合同实际金额为准，本 ADR 只锁定定价侧口径。
