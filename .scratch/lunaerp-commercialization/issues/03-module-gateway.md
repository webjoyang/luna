# 03-module-gateway: 模块套餐开通网关与菜单信息架构落地

Type: grilling
Status: resolved
Blocked by: 18

## Question

设计租户模块开通网关并产出 spec（对应 Q9=A / Q18），grilling 时先调 Skill "grilling" 与 "domain-modeling"：

1. 套餐-模块映射：模块清单编码化（lunaerp 现有+规划模块全集），套餐 = 模块集合；需决定复用芋道 TenantPackage（见 18 号研究结论）还是自建 lunaerp 模块开通表；
2. 双层控制实现点：前端菜单过滤 + 后端接口拦截（未开通模块的 API 返回明确错误码），给出拦截器的统一实现方案；
3. 开通/停用流程：停用时已有数据的处理策略（只读 vs 隐藏）；
4. 菜单信息架构迁移映射：按 Q18 的 9+1 一级分组（首页/基础信息/销售/生产/供应链/库存/样品/财务/审批中心/系统管理），产出"现有菜单 → 新分组"的完整映射表（含本图规划中的新模块落位）；
5. 脱敏范围划定移交说明：固定敏感字段清单在 04 号 ticket 内细化，本 ticket 只确认网关不含字段级配置。

产出：`.scratch/module-gateway/spec.md`（按统一 DoD）。

## Answer

grilling 一轮锁定 5 个决策，spec 落 `.scratch/module-gateway/spec.md`：

1. **套餐-模块映射**：复用芋道 `TenantPackage`，**不另建模块表**。模块粒度 = 一级菜单目录（`system_menu` 中 `type=1 AND parent_id=0`），套餐 `menuIds` 勾一级目录 id 即开通其整棵菜单树。模块全集 = 基础信息(10000)/销售(10100)/生产(10200)/库存(10300)/样品(10600)/财务(10700)/审批中心(10800) + 系统管理+首页（芋道内置，必含）。
2. **双层控制**：**不加后端拦截器**（Q2=C）。前端靠 TenantPackage 菜单裁剪（已有），后端靠 `@PreAuthorize` 返回 403（已有）。前端 axios 拦截器对 403 提示"模块未开通"。不新增注解、不新增错误码。
3. **停用策略**：**隐藏**（Q3=B）。从套餐 `menuIds` 移除整棵菜单树，用户完全看不到；数据保留在库不归档，重新开通即恢复。
4. **菜单 IA 迁移**：现有一级分组改名（基本信息→基础信息、业务管理→销售、生产管理→生产、库存管理→库存、样品管理→样品），**不设"供应链"分组**（Q4）；纱线采购/发染记录归生产，供应商信息留基础信息，入库管理留库存。新模块落位：销售退货/出口单证/客户对账→销售；成本报价/打色单/发胚拆分/排产齐套→生产；供应商对账/资金费用工资→财务；审批中心→10800（02 号落地）。
5. **脱敏移交**：网关不含字段级配置，固定敏感字段清单由 04 号 ticket 细化（芋道注解级脱敏）。

不新建表、不新增拦截器、不新增 API，全部复用芋道 `system_tenant_package` + `TenantPackageService` + `@PreAuthorize`。
