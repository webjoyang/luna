# ADR-0014：检验录检明细作为独立子资源（刻意不一致 ADR-0003）

**状态**：Accepted
**日期**：2026-09-21
**关联**：生产管理-检验单 MVP、ADR-0003

## 背景

项目里生产单据的明细均遵循 ADR-0003 聚合保存模式：明细随主表整体加载、整体保存、级联删除，没有独立操作界面。已落地的合同明细、胚布颜色投胚分配、染色颜色明细、纱线采购明细全部如此。

参考项目（linaagi）的 `inspectionResult` 是逐条增删的独立子表。若检验录检明细也走聚合保存模式，一单几十至上百卷的录检场景下整体保存性能差、多人并行录检时易冲突、单卷保存粒度过粗。

## 决策

检验录检明细（`InspectionOrderItem`）**作为独立子资源处理**，与供应商联系人/客户联系人模式同构：有自己的 CRUD 端点与权限码（`lunaerp:production:inspection-order-item:`），逐卷增删改，不随主表整体保存替换。这是与 ADR-0003 聚合保存模式的**刻意不一致**。

## 理由

录检的业务节奏与合同明细/颜色分配那种"一次性填好整体保存"的节奏不同：
- **高频逐卷录入**：每检验一卷就保存一次，聚合保存需每次重传整张明细表。
- **量可能很大**：一单几十至上百卷，整体加载/保存的 IO 与序列化成本高。
- **多人并行录检**：不同检验员可能同时录不同卷，聚合保存的整体替换会互相覆盖。
- **单卷粒度操作**：删除一卷、修改一卷的 grade，应是单条请求而非整表重传。

级联删除仍然保留（删主表时同事务把该单所有明细 `deleted=1`），与 ADR-0003 的级联模式一致——独立子资源只影响"增改查"的粒度，不影响"删"的级联语义。

## 反向权衡

- **不一致成本**：项目里生产单据明细从此有了两种模式（聚合 vs 独立子资源），需在 GLOSSARY.md 与代码注释中明确标注，避免后续开发者误用。
- **端点与权限码增多**：明细多了独立的 4 个 CRUD 端点与 4 个权限码、4 个菜单按钮节点（type=3）。
- **取舍**：录检高频逐卷操作的业务特点使得独立子资源的收益覆盖上述成本。
