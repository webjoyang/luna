# 0007 — 胚布单引用供应商角色时不做类型强过滤

## 状态

accepted

## 上下文与决定

胚布单通过四个字段引用供应商档案：`greige_factory_id` + `greige_factory_name`（承织坯布厂，必填）、`dyeing_factory_id` + `dyeing_factory_name`（指定染厂，可空），名称为建单时的公司名快照。

表单中的坯布厂/染厂远程选择器**不按供应商类型（`supplierType`）过滤**：两个选择器都检索全部 `ACTIVE` 供应商，选项中展示"供应商编号 + 公司名 + 类型小标签"辅助人工辨认；保存时后端只校验引用供应商的**存在性与租户归属**，不校验其类型是否为坯布厂/染厂。

## 理由

1. **旧系统的设计证据**：旧系统（linaagi）坯布厂选择器完全不按类型过滤（全部供应商 + 允许自由文本）；染厂选择器虽按类型正则（`/染厂|染色|染整|扎染|印染|小缸|水洗|后整理/`）过滤，但代码注释明确其仅为 "helpful" 辅助，**一旦无任何命中立即回退展示全部供应商**。类型过滤在旧设计中从来不是强约束。
2. **字典口径注定不全**：供应商类型字典 `lunaerp_supplier_type` 共 18 项且一个供应商只能挂一个类型值。其中旧染厂正则覆盖的"染整""后整理"环节没有对应编码；扎染（`TIE_DYEING`）、印染（`PRINTING_MILL`）、小缸厂（`SMALL_VAT_MILL`）、水洗厂（`WASHING_MILL`）分散在多值上。按类型强过滤或多值 IN 过滤都必然漏掉实际承接这些工序的供应商。
3. **防止历史/边界数据被挡**：保存口径一旦变严，供应商类型被修改或归类与本单角色不一致时，老单将无法编辑保存。用"类型标签可见"替代"类型强过滤"，既防误选又不丢数据。

## 考虑过的备选

- **严格类型过滤**（坯布厂 `GREIGE_MILL`、染厂 `DYEING_MILL`）：无旧系统依据，且漏选类型细分错位的供应商，已不推荐。
- **染厂多类型 IN 过滤**（`DYEING_MILL/TIE_DYEING/PRINTING_MILL/SMALL_VAT_MILL/WASHING_MILL`，无命中回退）：贴合旧染厂正则，但需改动供应商分页接口，且"染整/后整理"仍无编码、集合口径随字典演进而腐化，维护成本高于收益。
- **允许自由文本不引用档案**：旧坯布厂的兜底形态，但放弃了主数据关联与快照价值；供应商档案已上线，不再需要。

## 后果

- 未来工程师看到"引用了供应商档案却不过滤类型"，**不应**将其"修复"为按 `supplierType` 强过滤；类型标签只承担展示职责。
- 选择器附加 `status = ACTIVE` 过滤：停用供应商不进入新单选项；历史单据上的名称快照与已保存 id 的展示不受影响。
- 引用的供应商事后被软删时，详情仍可显示快照名称；保存该单时存在性校验会失败，需重新选择有效供应商（与合同引用客户的处理同构）。
