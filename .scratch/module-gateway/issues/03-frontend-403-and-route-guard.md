# 03: 前端 403 拦截器与未开通模块路由守卫

**What to build:** API 返回 HTTP 403 时，`luna-ui/src/utils/request.ts`（或现有 axios 响应拦截器）区分两类场景：① 当前路由对应的菜单不在 `permissionStore.getAddRouters` 中（模块未开通）→ 提示「该模块未开通，请联系管理员」并跳转首页；② 菜单存在但操作按钮级权限不足 → 提示「无操作权限」。直接在浏览器地址栏访问未开通模块的 URL 时，前端路由守卫重定向到首页（而非 404 页）。既有非 403 响应处理不受影响。

**Blocked by:** None（可立即开始；独立前端改动，不依赖后端 SQL）

**Status:** ready-for-agent

- [ ] axios 响应拦截器 403 分支就位，与现有 401/500 等分支并存不冲突
- [ ] 模块未开通场景（路由不在 `permissionStore.getAddRouters`）→ 提示「该模块未开通，请联系管理员」并跳转首页
- [ ] 操作权限不足场景（菜单存在、按钮级 403）→ 提示「无操作权限」，不跳转
- [ ] 直接访问未开通模块 URL（如 `/production/xxx`）时路由守卫重定向首页，不显示 404
- [ ] 既有非 403 响应处理逻辑与提示文案未受影响
- [ ] 文案与 spec「前端 403 处理约定」一致
