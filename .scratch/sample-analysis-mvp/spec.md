# 样品管理 - 样品分析 MVP

Status: ready-for-agent

> 术语以 [docs/contexts/sample/CONTEXT.md](../../docs/contexts/sample/CONTEXT.md) 为权威，架构取舍见 [ADR-0036](../../docs/adr/0036-sample-analysis-non-document-record-hybrid-storage.md)。

## Problem Statement

客户（或潜在客户）经常寄来一块针织布样，要求公司回答三个问题：这是什么布、这种布怎么做、大概多少钱一匹/一米。业务员/分析员拿到布样后，需要：

1. 登记来样信息（谁寄的、客户款号、成品门幅/克重/成分）；
2. 反推针织工艺——用哪几种纱、各占多少比例、大圆机用什么机台参数、纱线在各路怎么绕、针盘三角怎么排列；
3. 基于纱价与工费染费估算内部成本，给出对外报价。

同时，分析服务本身按条月结收费（默认 30 元/条），月底要能清楚统计哪些客户的分析费已收、哪些未收、一共多少条。

旧系统（linaagi）已有这套功能，但技术栈与新 Luna ERP 不兼容，且把纱线明细、绕纱、机台参数、三角画板、供应商报价全部塞进 JSON 字符串无法行级校验，成本公式还存在"其他费用漏算、损耗率越界静默兜底"等缺陷。业务员现在没有任何新系统界面可用。

## Solution

在新系统建立继基本信息/业务管理/生产管理/库存管理之后的**第五个顶级业务域：样品管理（sample）**，其第一个功能是**样品分析**。样品分析是一份**分析记录/报告**，不是流转单据：没有状态机、没有审批、不触发任何库存或生产单据。

提供一个传统分页列表页与一个整页工作台：

- **列表页**：缩略图、样品编号、客户、产品、款号、门幅、克重、登记人、月结单价、付款标签；关键字搜索 + 付款三态筛选；顶部三张统计卡（未付金额/已付金额/任务总数）；多选批量标记付款。
- **工作台三个页签**：① 来样信息（客户与来样属性、9 张照片）② 针织工艺（15 个机台参数、纱线规格明细子表、绕纱行子表、三角排列 5 态画板）③ 成本报价（费用与服务端重算的总成本、供应商报价登记、对外报价、月结收费）。

数据按形态混合存储：固定标量（含 15 个机台参数）拍平主表；三块多行结构（纱线规格明细、绕纱行、供应商报价）用三张聚合子表随主表一起保存；三角画板与照片用 JSONB 列。纱线明细行必须从纱线材质/规格档案下拉选择并快照；客户与供应商允许"挂档案"也允许纯手填。编号由服务端按 `SA+年份+4位流水` 生成、可手填、提供预览。

## User Stories

### 菜单与入口

1. 作为业务员，我想在主导航看到"样品管理"顶级菜单及其下"样品分析"入口，以便进入样品分析列表。
2. 作为没有样品分析查看权限的角色，我不应该看到该菜单，直接访问其 URL 也应被拒绝。
3. 作为有权限的业务员，我想从列表点"新建"打开空白工作台，点任意一行打开该记录的只读工作台。

### 列表浏览与查询

4. 作为业务员，我想以分页表格（每页 10 条）浏览样品分析，列含照片缩略图（第一张照片）、样品编号、客户、产品名称、客户款号、门幅、克重、登记人、月结单价、付款状态标签、登记日期。
5. 作为业务员，我想用一个关键字框同时模糊搜索样品编号、客户名、产品名、客户款号、成分，以便快速定位。
6. 作为业务员，我想按付款状态筛选：全部 / 未付款 / 已付款，以便月底对未收款集中催收。
7. 作为业务员，我想在列表顶部看到三张统计卡：未付金额、已付金额、任务总数，以便掌握收费全局。
8. 作为业务员，我希望我切换搜索或付款筛选时，三张统计卡与列表使用同一筛选口径一起刷新，但统计数字不随分页变化。
9. 作为业务员，我想付款状态在列表里以醒目标签呈现（未付/已付颜色区分），一眼可辨。

### 来样信息

10. 作为业务员，我想通过下拉搜索选择客户档案：选中后系统保存客户 ID 与客户名称快照。
11. 作为业务员，对于散客或临时来样，我想允许不选客户、直接手填客户名称也能保存。
12. 作为业务员，我想手填联系人与客户款号（自由文本），因为来样联系人经常是一次性对接人。
13. 作为业务员，我想填写产品名称（必填）、成分、门幅（CM）、克重（GSM）；产品名可基于产品档案做联想填充，但只填文字、不绑定产品档案。
14. 作为业务员，我想保存后看到系统自动算出的米长（每公斤米数），门幅或克重没填/填了非正数时米长留空显示"-"，无需我手算。
15. 作为业务员，我想给样品上传最多 9 张照片，支持上传后预览、删除、按上传顺序展示。
16. 作为业务员，我想在列表只加载第一张缩略图、在工作台才加载全部照片，避免列表卡顿。
17. 作为业务员，我想删除照片时只是把照片从该样品移除，不影响文件服务里的文件本身。

### 针织工艺：分类与机台参数

18. 作为分析员，我想从下拉选择工序（染色/色织/印花/刺毛）、双染工艺（单染 T/C/R/N/M/天丝、双染 TR/CVC/TC/NR/TN/TM、三染 NTR 共 13 项）、机型（喷水织机/大圆机/经编机/剑杆织机），三项都可以留空。
19. 作为分析员，我想填写实测产量以及 11 个机台参数自由文本（花号、白胚门幅、白胚克重、花宽、花高、齿轮、布架、开机转数、送纱盘、理论产量、线长），因为这些值常含单位、分数等混合写法。

### 针织工艺：纱线规格明细

20. 作为分析员，我想在纱线规格明细子表中先选材质、再选该材质下的纱线规格（复用纱线档案的级联下拉，支持关键字检索），选中后系统自动带出纺法与参考单价。
21. 作为分析员，我想自动带出的单价可以修改（纱价随行就市），并为每行填写用纱比例（百分比）与备注。
22. 作为分析员，我想新增、删除任意明细行；每行必须来自纱线档案，不允许手打一条档案里没有的纱线。
23. 作为分析员，当各行比例合计不等于 100% 时，我想看到"不足/超标"的文字提示，但系统不阻止我保存（先记后核是常态）。
24. 作为分析员，我想填 0 或负数比例时被表单拦截，因为比例必须为正数。
25. 作为分析员，我想即使某条纱线档案后来被停用或删除，历史样品分析上仍能看到当时快照下来的材质、规格、纺法。

### 针织工艺：绕纱与三角画板

26. 作为分析员，我想维护绕纱行子表：每行可填路号、绕纱表述（如"25.1cm/1 花宽"）、对针（如"第一路对针"）、描述（如"开幅线"），全部可空，可自由增删行。
27. 作为分析员，我想使用三角排列画板：默认 4 行 × 24 列，每点击一个格子按 空 → v 成圈 → - 集圈 → + 浮线 = 其它 循环切换符号。
28. 作为分析员，我想把画板每次增加或减少 4 列以适配不同花型循环，也想一键清空重画。
29. 作为分析员，我想画板内容随样品保存，再次打开时完整还原行列数与每格符号。

### 成本报价

30. 作为分析员，我想系统自动汇总纱线成本（各明细行 单价 × 比例 ÷ 100 之和），单价误填成吨价（>1000，如 23000）时系统自动按 ÷1000 处理。
31. 作为分析员，我想填写生产工费、染整费、其他费用与损耗率（百分比，如 5 表示 5%）。
32. 作为分析员，我想系统按 `(纱线成本 + 生产工费 + 染整费 + 其他费用) ÷ (1 − 损耗率/100)` 给出总成本并保留两位小数，其他费用必须计入。
33. 作为分析员，当我把损耗率填成 100、负数或非法值时，我希望保存被明确拒绝并收到错误提示，而不是系统悄悄换一种算法。
34. 作为分析员，我想在编辑时看到成本的实时预览辅助录入，但以保存后系统返回的最终值为准。
35. 作为分析员，我想登记供应商报价行：联想选择供应商（保存 ID + 名称快照）或直接手填供应商名称，填胚布报价与备注；这些报价只作参考，不进总成本。
36. 作为分析员，我想即使报价供应商后来被停用，历史报价行仍正常展示与保存，不被拦截。
37. 作为业务员，我想填写对外报价（元/米）与报价备注，它们纯登记，不影响内部成本与收费统计。

### 月结收费

38. 作为业务员，我想每条样品分析有月结单价（缺省 30 元/条，可改）与付款状态（缺省未付）。
39. 作为有"收费"权限的人员，我想在列表勾选多条后一次性标记为已付款或未付款（操作前二次确认）。
40. 作为有"收费"权限的人员，我想在工作台切换单条记录的付款状态。
41. 作为只有普通编辑权限、没有"收费"权限的人员，我看不到任何改付款状态的入口，调用收费接口也应被拒绝。
42. 作为业务员，我想未付金额 = 所有未付记录月结单价之和、已付金额 = 所有已付记录月结单价之和；对外报价不参与这两个金额。

### 编号、登记人与删除

43. 作为业务员，我想新建时看到系统预览的下一个样品编号（SA + 今年年份 + 4 位流水号），但预览不占用号码。
44. 作为业务员，我想在特殊情况下手填样品编号；手填编号与已有记录（含已删除记录）重复时，保存被拒绝并提示编号重复。
45. 作为业务员，我想流水号在年份切换后从新年份重新计数，编号超过 9999 时自然扩位不报错。
46. 作为业务员，我想每条记录保留登记人（创建者姓名），登记时间之后的任何人编辑都不改变登记人。
47. 作为业务员，我想删除一条样品分析时它从列表消失（逻辑删除），其三个子表内容一并逻辑删除；已付款记录也允许删除，但前端必须二次确认。
48. 作为业务员，我想被删除记录的编号永不重用，避免历史沟通中的编号指向另一条记录。

### 数据隔离

49. 作为一个租户的用户，我只能看到、编辑、统计到本租户的样品分析，编号取号也只在本租户内排序。
50. 作为实现者，我希望客户、供应商、纱线规格档案被删除或停用时，样品分析的保存不被硬阻断、历史展示依赖快照字段仍完整可读。

## Implementation Decisions

### 领域定位与命名

- 新建顶级业务域 **sample（样品管理）**，后端按"层 → 业务域 → 子模块"落在 lunaerp 模块的 `sample.sampleanalysis` 包下（主表一个服务；三个子表仅 DO/Mapper/服务内部协作，不对外暴露端点）；前端临时实现区镜像 `sample/sample-analysis/`（列表 + 工作台）。
- 样品分析**不设业务状态字段、不做状态机、不接审批**；唯一生命周期信号是布尔付款状态。删除走框架逻辑删除。
- 金熊工艺单（旧系统与样品分析 95% 同构的 KC 单据）本期不做，不预留类型/entryMode 字段。

### Schema（4 张表，均继承多租户基类，均不建数据库物理外键）

**主表 `lunaerp_sample_analysis`**：

- 标识与关联：`sample_analysis_no`（租户内唯一、唯一索引含软删行）、`customer_id`（可空）、`client_name`（必填，快照或手填）、`client_contact`、`client_style_no`
- 来样属性：`product_name`（必填）、`composition`、`width`、`weight`、`meter_length`（服务端计算可空）
- 15 个机台工艺参数全部拍平为可空列：`process`、`dyeing_process`、`machine_type`（三个存字典 value）、`output`（文本），加 `flower_no`、`white_width`、`white_weight`、`flower_width`、`flower_height`、`gear`、`cloth_rack`、`start_speed`、`feeder_disk`、`theoretical_output`、`stitch_length`（11 个文本）
- JSONB：`photos`（infra 文件 URL 有序数组，业务上限 9）、`stitch_arrange`（画板，形状 `{ columns: number, rows: 4, data: string[][] }`，符号集合 `''`/`v`/`-`/`+`/`=`）
- 成本与报价：`production_cost`、`dyeing_cost`、`other_cost`、`loss_rate`（百分比数，校验 0≤x<100）、`total_cost`（服务端重算）、`quoted_price`、`quoted_remark`
- 收费：`is_paid`（布尔缺省 false）、`unit_price`（缺省 30）
- 登记人快照：`creator_id` + `creator_name`；另有 `remark`
- 子表关联索引：三张子表按 (tenant_id, sample_analysis_id) 建普通索引

**`lunaerp_sample_analysis_yarn_spec`（纱线规格明细）**：`sample_analysis_id`、`yarn_spec_id`（必填）、`yarn_type_id`、`yarn_type_name`、`spec_name`、`spin_method`（四项为档案快照）、`ratio`（正数）、`unit_price`、`remark`；不设行号，按保存顺序展示。

**`lunaerp_sample_analysis_yarn_arrange`（绕纱行）**：`sample_analysis_id`、`code`、`draft_text`、`border_status`、`description`（避让 SQL 保留词，不用 desc），全部可空文本。

**`lunaerp_sample_analysis_supplier_quote`（供应商报价）**：`sample_analysis_id`、`supplier_id`（可空）、`supplier_name`、`greige_price`、`remark`。

三个子表随主表 create/update **聚合差异保存**（新增/更新/删除差集，沿用 ADR-0032 模式），主表删除时三个子表级联逻辑删除。

### 字典（4 个，dict_type id 2251-2254，data id 自 3709 起）

- `lunaerp_sample_process`（2251）：DYEING 染色 / YARN_DYED 色织 / PRINTING 印花 / NAPPING 刺毛
- `lunaerp_sample_dyeing_process`（2252）：SINGLE_T、SINGLE_C、SINGLE_R、SINGLE_N、SINGLE_M、SINGLE_TENCEL、DOUBLE_TR、DOUBLE_CVC、DOUBLE_TC、DOUBLE_NR、DOUBLE_TN、DOUBLE_TM、TRIPLE_NTR
- `lunaerp_sample_machine_type`（2253）：WATER_JET / CIRCULAR_KNIT / WARP_KNIT / RAPIER
- `lunaerp_sample_spin_method`（2254）：环锭纺 / 赛络纺 / 紧密纺 / 紧密赛络纺 / 气流纺 / 涡流纺——**value 与 label 同为中文**（全项目唯一 value 用中文的字典），因为纱线档案 spinMethod 是存量中文的自由文本、明细存的是档案快照；快照值不在字典内也照常存储展示，不做强校验

三个工艺分类字段存字典 value 英文编码、不存 dict_data 数字 id（全项目字典惯例）；付款是布尔不建字典；机台 11 参数自由文本不建字典。

### 菜单与权限

- 顶级目录 **10600 样品管理**（type=1，sort 104，path `/sample`）；**10610 样品分析** 菜单（component 指向样品分析列表，权限标识 `lunaerp:sample:sample-analysis:query`）；按钮位 10611 创建、10612 修改、10613 删除、10614 收费。
- 五个权限动作：`query` / `create` / `update` / `delete` / `pay`；`pay` 独立授权（对标发货单 audit 独立分权），单条切换与批量标记共用同一端点。
- 初始化 SQL 必须可重复执行（DDL IF NOT EXISTS + 先按 id DELETE 再 INSERT 菜单/字典）。

### API 契约（前缀 /lunaerp/sample/sample-analysis，统一 CommonResult）

| 方法 | 路径 | 权限 | 契约要点 |
|---|---|---|---|
| GET | /page | query | 参数 pageNo/pageSize、keyword、isPaid（三态可空）；列表行只带第一张照片 URL |
| GET | /get | query | 参数 id；返回主表 + 三个子表数组（保序）+ 照片 URL 数组 |
| GET | /next-no | query | 无副作用预览下一个编号 |
| GET | /payment-stats | query | 接受与 page 同筛选，返回 unpaidAmount / paidAmount / totalCount |
| POST | /create | create | body = 主表字段 + 三个子表数组；返回新 id |
| PUT | /update | update | 同体；子表差异保存；重算米长与总成本 |
| PUT | /payment | pay | body `{ ids: number[], isPaid: boolean }`，单条与批量共用 |
| DELETE | /delete | delete | 参数 id；主表与三个子表级联逻辑删除 |

错误码段 `1-030-018`：000 样品分析不存在；001 样品编号重复；002 关联引用不存在（客户/供应商/纱线规格）；003 损耗率非法；100 纱线规格不存在。

### 业务规则

- **编号**：`SA` + 公历年 + 4 位顺序号（跨年从 1 起、超 9999 自然扩位），租户内全量唯一含软删行；缺省服务端取号、可手填、撞号报 001；next-no 只预览不落号。
- **米长**：`100000 / (门幅 × 克重)`，四舍五入 2 位；门幅/克重为空或非正则置 NULL。
- **成本（服务端权威）**：纱线成本 = Σ（明细单价 × 比例 ÷100），明细单价 >1000 自动 ÷1000；总成本 =（纱线 + 生产工费 + 染整费 + 其他费用）÷（1 − 损耗率/100），2 位小数；费用空按 0；损耗率 0≤x<100 否则报 003；供应商报价不进总成本；对外报价不进任何合计。
- **登记人**：创建时写入当前用户 id + 姓名快照，更新不改。
- **关联校验**：customerId / supplierId 非空时档案须存在（报 002），停用不拦截；yarnSpecId 必须存在（报 100），停用规格不拦截。
- **照片**：业务校验最多 9 个 URL；删除照片仅删数组元素；不物理删除 infra 文件。
- **画板**：服务端只做透传与形状校验（rows=4、data 为二维符号数组、符号在 5 态集合内），不参与任何计算。

### 前端交互决策

- 列表为 el-table 传统分页（非旧系统卡片墙）；工作台只读/编辑两态，三个 el-tabs 页签：来样信息 / 针织工艺 / 成本报价。
- 客户与供应商选择器为"档案搜索下拉 + 允许清空后纯手填名称"；纱线明细为"材质下拉 → 规格下拉"两级级联（复用纱线档案现有级联查询接口），选中一次性带出纺法/参考单价；比例合计 ≠100% 仅文字提示不拦截。
- 画板为 Element Plus 按钮网格（非 canvas 手绘），格子点击循环 5 态，+4/-4 列与清空按钮。
- 成本区在编辑态用纯函数做前端实时预览，保存成功后以服务端返回值覆盖。
- 字典展示统一用项目字典标签组件；未付/已付标签颜色在字典数据 seed 中配置（danger/success）。
- 前端表单校验：产品名称必填；明细比例 >0；损耗率 0≤x<100；月结单价 ≥0；照片 ≤9。

## Testing Decisions

好测试的标准：**只验证服务对外行为，不绑定内部实现**（不断言私有方法、不校验 SQL/JSON 内部结构）；测试名描述业务规则；不重复测试框架能力（多租户过滤、逻辑删除、分页、权限拦截本身由框架保证，只在与本模块业务规则交叉处测一两个代表用例）。

共两个测试接缝，沿用现有接缝、不引入集成测试或 Controller 测试：

1. **后端：样品分析服务单元测试（Mockito，Mapper 全部 Mock）**——本功能唯一后端接缝，对标本模块既有 `YarnOrderServiceImplTest`、`ShipmentServiceImplTest` 的风格（@InjectMocks + Mock Mapper，无 Spring 上下文、无数据库）。覆盖：
   - 编号：自动取号递增、跨年重置、超 4 位扩位、手填合法、手填撞号 001、软删行占号且不重用
   - 米长：正常值与两位小数；门幅/克重缺失、0、负数 → 空
   - 成本：多行纱线加权、单价 >1000 自动 ÷1000、其他费用计入、损耗率除法结果、损耗率 100/负数报 003、空费用按 0
   - 聚合保存：更新时三个子表的增/改/删差异正确落库；删主表级联软删三个子表
   - 收费与统计：批量标记只影响指定 id；未付/已付金额与总数口径（对外报价不计入）
   - 关联校验：客户/供应商/纱线规格不存在分别报错；停用档案不拦截
   - 登记人：创建写快照、更新不变更
   - 多租户代表用例：取号与查询按租户隔离
   - 若米长/成本计算抽为纯函数（对标产品模块成本纯函数的先例），仍只通过本服务测试覆盖，不另开测试类
2. **前端：成本预览纯函数 vitest 测试（1 个 spec）**——本功能唯一前端接缝，对标现有 `product-yarn-cost.spec.ts`：验证前端预览与服务端同口径（加权、>1000 容错、其他费用、损耗率边界）。画板、表单、列表等 Vue 组件不写组件测试，与 lunaerp-elmui 全部既有模块一致，靠手工验证。

错误码段位冲突由现有的全局错误码常量测试兜底，不新增测试。

## Out of Scope

以下能力本期**明确不做**，不建字段、不建菜单、不留占位：

- AI 显微镜/OCR 拍照识别自动回填
- 分析报告打印四组合、分享海报与二维码
- Excel 批量导入/导出
- 自定义字段（旧系统 extensionData 动态表单）
- 审批流、任何业务状态机、事业部归属（businessOwnership）
- 金熊工艺单（KnittingCraftOrder，KC 编号）及其独立入口
- 样品库存台账、寄样登记、客户门户样品展示
- 财务系统对接、账期账单、收款核销（仅做 isPaid 布尔登记）
- 旧系统历史数据迁移
- 前端组件测试/E2E 测试、后端集成测试与 Controller 层测试

## Further Notes

- 与旧系统的**有意口径差异**（不承诺逐单算出同一数值）：其他费用计入总成本；损耗率越界直接报错而非静默改加法；旧的 processingFee / productionCost 双工费字段合并为一个生产工费；机台参数/纱线/绕纱/供应商报价从 JSON 改关系表；照片从 base64 改文件服务 URL；客户/供应商/纱线从纯文本联想改为 ID + 快照（客户与供应商仍允许手填）。
- 供应商报价行不做旧系统"供应商必须 ACTIVE"守卫。
- 照片排序 MVP 按上传顺序；若拖拽排序实现成本高，允许退化为"删除后保持剩余顺序 + 新上传追加末尾"。
- 工作台打开方式（菜单驱动路由 + query id 的独立页，或列表页内抽屉）实施时对齐 lunaerp-elmui 当时最新模块先例（纱线采购单/检验单模式），不改变本 spec 的行为契约。
- 领域词汇（样品分析、绕纱行、三角排列画板、月结收费等）以 sample 域 CONTEXT.md 为准，实现中避免重新发明近义词。
