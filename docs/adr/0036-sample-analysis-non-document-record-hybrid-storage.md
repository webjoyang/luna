# ADR-0036：样品分析——非单据型分析记录的建模与混合存储

**状态**：Accepted
**日期**：2026-10-04
**关联**：样品管理域样品分析；ADR-0003（聚合子表模式）、ADR-0010（纱线采购/服务端成本计算）、ADR-0032（聚合子表差异保存）、ADR-0004/0005（编号规则）

## 背景

旧系统（linaagi，仓内 `oldserver`/`oldweb`）"样品系列-样品分析"（Prisma `SampleAnalysis`，SA 编号）记录客户寄来针织布样后的来样登记、针织工艺反推（纱线规格、绕纱、大圆机三角排列）、成本估算与对外报价，并按条收取月结分析费。旧实现有三个结构性问题需要在迁移到新栈（Spring Boot + MyBatis Plus / Vue3 + Element Plus）时决策：

1. **它不是流转单据**：旧表有 `status`（ACTIVE，后期审批流终态回写落点），但业务上没有下达/审核/过账动作，也不驱动任何下游单据。
2. **存储一锅炖**：纱线规格明细、绕纱行、供应商报价、机台 11 参数、三角画板全部以 JSON 字符串塞进主表列，无法做行级校验、关联校验与后续查询。
3. **成本公式有历史包袱**：`otherCost` 其他费用有录入入口却漏算；损耗率越界时走"改除法为加法"的静默兜底；`processingFee` 与 `costData.productionCost` 双字段互兜底。

旧系统另有字段约 95% 同构的金熊工艺单（`KnittingCraftOrder`，KC 编号，独立表/独立入口），本期明确不迁移。

## 决策

### 1. 定性：非单据型分析记录——无状态机、无审批、无下游联动

样品分析是一张**分析记录/报告**：不设业务状态字段、不做状态机（不套 DRAFT/ACTIVE/COMPLETED/CANCELLED），不接审批流，不触发库存/生产任何单据或流水。唯一的生命周期信号是独立的布尔付款状态 `isPaid`（月结收费），并以独立 `:pay` 权限与普通编辑分离（对齐发货单 `:audit` 独立分权）。登记人建单时快照、不随编辑改变。删除为软删除、不设业务硬守卫（已付也可删，前端二次确认）。

样品分析作为新的第五个顶级业务域 **sample（样品管理）** 承载（菜单 10600 起、错误码段 1-030-040；2026-10 自 1-030-018 段迁入避让发染记录重号，见 shared GLOSSARY 历史避让记录），为未来样品库存、寄样登记留位；本期不建这两个模块，也不预留 entryMode/类型字段。

### 2. 混合存储：3 子表 + 主表拍平 + 1 JSONB，替代旧全 JSON

| 数据 | 形态 | 理由 |
|---|---|---|
| 纱线规格明细 | 独立子表 `lunaerp_sample_analysis_yarn_spec` | 行字段参与服务端成本重算，且行级强制关联纱线规格档案（`yarnSpecId` 必填）+ 档案快照，需要行级校验 |
| 绕纱行 | 独立子表 `lunaerp_sample_analysis_yarn_arrange` | 典型可增删明细行（路号/绕纱表述/对针/描述），随主表聚合差异保存（ADR-0032），与旧 JSON 相比可逐行维护与未来检索 |
| 供应商报价登记 | 独立子表 `lunaerp_sample_analysis_supplier_quote` | 含供应商 ID 逻辑关联与快照、胚布报价；虽本期不参与总成本，但行级关联校验与扩展需要真实行 |
| 机台 15 参数 | 全部拍平为主表列 | 每单固定一组标量（工序/双染工艺/机型/实测产量 + 11 个可空文本），无多行结构、无子资源语义 |
| 三角排列画板 | 主表单个 JSONB 列 `stitch_arrange` | 一整块不可拆分的 4×N 网格工艺图，无逐格查询/计算需求；结构 `{columns, rows, data}`，JSONB 是其自然形态 |
| 照片 | 主表 JSONB 列 `photos`（≤9 个 infra 文件 URL 有序数组） | 不沿用旧系统 base64 入库；删照片只删 URL 关联，不物理删 infra 文件 |

三个子表均无独立 Controller/端点/权限码，随主表 create/update 聚合保存、级联软删（ADR-0003 模式）；与主表、与引用档案之间**一律不建数据库物理外键**（全项目逻辑关联惯例），删除被引用档案不级联、不硬阻止，历史记录靠快照留存。

### 3. 纱线明细强关联档案、纺法字典 value 存中文

纱线明细行必须从纱线材质/规格档案（production 域）下拉选择（复用 `GET /lunaerp/production/yarn-spec/cascade-options`），不提供自由文本规格行；选中后快照材质、规格名、纺法，单价缺省带档案 `refPrice` 可改。成品侧的产品名/成分/门幅/克重则保持自由文本、不挂产品档案——来样是"未知布样的反推结果"，且多数样品永不变成在售产品。

工序/双染工艺/机型走三个新字典、**存字典 value 英文编码**（全项目字典惯例）。纺法字典（2254）例外：**value 直接存中文**（环锭纺等 6 项，对齐旧系统 SPINNING_METHOD），因为档案 `spinMethod` 本身是自由文本且存量为中文，明细存快照值，中文 value 才能与档案及标签渲染天然一致；快照值不在字典内也照常存储展示，不做强校验。

### 4. 成本公式搬家即修正，服务端权威重算

- 米长 `meterLength = 100000 / (门幅 × 克重)`，保存时服务端计算落库，输入缺失/非正即为 NULL；
- 纱线成本 = Σ（明细单价 × 比例/100）；单价 >1000 自动 ÷1000 的容错**保留**（防元/吨误填，集中在服务端）；
- `totalCost = (纱线成本 + 生产工费 + 染整费 + 其他费用) ÷ (1 − 损耗率/100)`，四舍五入 2 位；
- `otherCost` **计入总成本**（修正旧漏算）；损耗率为百分比数字（5=5%），API **硬校验 0≤lossRate<100、越界报错**，废除旧的静默加法兜底；
- 旧 `processingFee` 与 `productionCost` 双字段合并为"生产工费"单字段；供应商报价行不参与总成本，不做"供应商必须 ACTIVE"守卫。

### 5. 编号与收费对齐既有惯例

样品编号 `SA + 年份 + 4 位流水`（超 9999 扩位），租户内全量唯一含软删行、不重用，服务端生成可手填（撞号报错），提供预览下一编号接口（ADR-0004/0005 模式）。月结收费：`unitPrice` 默认 30 元/条可改，单条/批量付款切换共用一个端点；收费统计按 unitPrice 聚合未付金额、已付金额、任务总数，对外报价 `quotedPrice` 与收费统计无关。

## 后果

- 样品分析在新系统中形态清晰：一份可增删改查、可收费、无任何流程负担的分析记录；未来接 AI/OCR、报告打印、寄样联动时有独立域与稳定模型可依附。
- 混合存储比旧全 JSON 多了 3 张子表与聚合差异保存的实现成本，换来行级校验（纱线必填、损耗率/比例数值校验）、档案关联与后续查询能力；画板/照片保留 JSONB 避免过度建模。
- 成本口径与旧系统**不完全一致**（otherCost 计入、损耗率越界报错、双工费合并）：同一组输入两系统总成本可能不同；这是有意修正，迁移文档与 spec 中显式标注，不承诺与旧值逐单对齐。
- 纺法字典 value 用中文是全项目字典惯例的唯一例外，后续新增需要与纱线档案自由文本对齐的字典时参照本例。
- 明确延后（不进 MVP）：AI 显微镜/OCR 回填、报告打印四组合、分享海报/二维码、Excel 批量导入、自定义字段（extensionData）、审批流、事业部归属、金熊工艺单、样品库存台账、寄样登记。
