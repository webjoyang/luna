# ADR-0031：进度反馈作为染色颜色行上的状态覆盖层（缸级粒度、零展示快照）

**状态**：Accepted
**日期**：2026-09-28
**关联**：生产管理-进度反馈 MVP；参考系统 linaagi 的 progress-feedback 模块；依赖 ADR-0032 先行落地

## 背景

外发染色的生产过程发生在公司外部的染厂，内部跟单员只能靠电话/微信获知"下单的布做到哪道工序"，是整条业务链上唯一的进度黑盒：自织织造进度已由布票体系自动推导，外发胚布进度与全链路看板本期不做。

参考系统 linaagi 的方案是：`ProgressFeedback` 不作为独立单据，而是按"合同+产品+颜色（+缸号）"自然键挂在销售合同/染色通知单之上的**执行状态覆盖层**，列表把源单据行与反馈状态聚合成"物料单元"，没有反馈的行显示"未排缸"；另有缸卡墙、自定义工序链、反馈流水等重功能。新系统需要决定这套模式如何落到 lunaerp 的数据模型与既有惯例中。

## 决策

1. **覆盖层，不做独立单据、不增强染色单**：进度反馈只回答"染厂做到哪了、发生过什么"，以染色颜色明细行（`DyeingColor`）为骨架做只读投影，不回写染色单的任何字段（零回写惯例），染色单侧仅在工作台加一个只读"进度反馈"页签作为第二入口。
2. **缸级粒度**：反馈最小单位是"一缸"（反馈缸 ProgressVat），持稳定的 `dyeingOrderId` + `dyeingColorId` + `vatNo`；一个颜色行可分多缸。`NOT_SCHEDULED 未排缸` 不是落库状态，而是"该颜色行下零反馈缸"的覆盖层虚拟态，列表以虚拟行/虚线建缸卡呈现。
3. **零展示快照（刻意不一致全项目惯例）**：反馈缸表只存关联 ID 与自身数据（缸号、数量、匹数、状态、五阶段日期、延期原因、备注），合同号/客户/染厂/产品/颜色等展示信息**一律不冗余**，查询时经染色单主表与颜色行子查询实时取出。
4. **稳定行 ID 以前置改造为前提**：染色颜色明细原随染色单"先删后插"，行 ID 每次保存变化，无法承载覆盖层关联。因此进度反馈不采用 linaagi 的"文本自然键 JOIN"，而是要求 ADR-0032 的聚合子表差异保存先落地，直接持有稳定的 `dyeingColorId`。
5. **固定六工序链**：`NOT_SCHEDULED → SCHEDULED → DYEING → FIXING → QUALITY_CHECK → COMPLETED`，逐格推进并由后端自动盖阶段日期戳；日期可修正、状态可回退（二次确认）；不引入参考系统的自定义工序模板/工序组合器。无取消态，录错的缸直接删除，颜色行回到虚拟未排缸。
6. **反馈流水为独立子资源**：缸下反馈记录（文字 + 问题标记 + 闭环时间）按 ADR-0014 模式逐行增删，只增不改、闭环问题不可删除；MVP 不含照片/视频附件（lunaerp 业务侧尚无文件上传使用先例）。
7. **内部跟单员代录**：不设染厂外部账号、不做移动端；无业务编号（同 ADR-0009）；延期 = 当前日期晚于染色单交货日期且未 COMPLETED；排产覆盖率（已建缸数量合计 ÷ 颜色行染色数量）只读计算，超排警告不拦截。
8. **删除守卫**：染色单更新移除颜色行时，若该行下存在反馈缸，硬拦截报错（错误码 1-030-017-004），与仓库/库位/织机"被引用禁删"惯例一致，保证覆盖层零悬挂、零孤儿。

## 理由

1. **覆盖层贴合跟单心智**：跟单对象不是"我要录一张单"，而是"染厂这批颜色做到哪了"。源数据（需求量、交期、染厂）已在染色单权威存在，再建一张独立单据必然产生双源同步问题；直接给染色单加动态字段又混淆了制单静态数据与高频反馈数据，且染色单四态无法表达工序级进度。
2. **零快照是覆盖层定位的直接推论**：本项目其他单据存 ID+名称快照，是为了"上游改名不影响历史凭证"；进度反馈不是凭证，价值恰在于反映**当前**实况——染色单上的合同/客户/染厂快照改名时，反馈列表理应立即跟随。若反馈表再存一份名称快照，反而引入第二份可能漂移的副本。代价是列表查询必须 JOIN，可接受（跟单数据量级为分页查询）。
3. **稳定 ID 关联优于文本自然键**：linaagi 用"合同号+品名+颜色文本"做键，是因其源行无稳定身份；lunaerp 具备改造条件，ID 关联更可靠，改名/改数量也不再产生悬挂（整行删除由守卫兜底）。
4. **固定六步足够 MVP**：参考系统的自定义工序链是为多染厂工艺分化设计的重功能；当前跟单核心诉求是"卡在哪道工序、是否延期、发生过什么问题"，固定链全部覆盖，且统计口径统一。

## 考虑过的备选

- **独立反馈单据 + 选择带入 + 全量快照**（项目最"惯例"的方案）：CRUD 最规整，但反馈与染色单变成两份需同步的数据，未反馈的行不可见，失去覆盖层"未排缸也看得见"的核心价值。否决。
- **直接增强染色单/颜色行**（加缸号与阶段日期字段）：一颜色行多缸无法表达，且高频反馈与低频制单耦合在同一聚合，编辑染色单的并发与权限边界混乱。否决。
- **文本自然键 find-or-create**（linaagi 原样照搬）：在颜色行 ID 可稳定后没有必要继续承担改名漂移风险。否决。
- **自定义工序模板 + 照片附件 + 缸卡墙全部重功能**：工序组合器、12 小时滞留预警、矩阵视图、实时推送、AI 洞察、语音录入均划出 MVP；缸卡墙仅复刻信息架构，用 Vue3 + Element Plus 桌面版重建。

## 后果

- 新建两表：`lunaerp_production_progress_feedback`（反馈缸）与 `lunaerp_production_progress_feedback_note`（反馈记录）；表上不建名称快照列、不建数据库唯一约束（缸号重复由 service 层校验）。
- 覆盖层列表以染色颜色明细行为骨架分页（仅聚合 ACTIVE/COMPLETED 染色单；DRAFT/CANCELLED 排除），反馈缸经 LEFT JOIN 挂载；缸数量合计与覆盖率在查询侧聚合。
- 染色单删除（软删）后其反馈缸默认从列表隐藏，预留"含已失效"筛选；反馈缸删除不影响染色单。
- 交付分两阶段：阶段一 ADR-0032 差异保存改造（七个既有聚合子表），阶段二进度反馈功能。
