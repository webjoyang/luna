## 2. 验收运行契约

### 2.1 环境与库

- **部署环境**：一台干净 Linux 机器（2C4G 起，文档中给最低/推荐配置），仅装 Docker+compose v2；按 install.md 执行 `docker compose up -d` 四服务起来且健康检查通过，即部署 gate 通过。
- **验收库**：compose 空库 → 跑 `install/` 编号总入口 → 默认 seed 落位 → 冒烟在其上造数。**每轮全链冒烟重建验收库**（compose down -v → up → install → seed），冒烟脚本不写自清理逻辑，保持脚本线性可读。
- **性能库**：与验收库同构，另跑 perf-seed 灌数；性能测量不与功能冒烟混用库实例。

### 2.2 P95 硬指标测量方法（统一口径，终结扯皮）

1. 每个"常规分页列表"对应主表灌 **10 000 行**：租户 A 9000 行 + 租户 B 1000 行，其中含约 5% 软删行、覆盖各状态值与时间跨度（≥12 个月）。
2. 以租户 A 身份对列表接口（含默认筛选与常用组合筛选各一）连续请求 **100 次，第 1 次预热丢弃**，记录后 99 次 P95。
3. 通过线：**P95 < 1000ms**；同时附 EXPLAIN：走索引（seq scan 即失败）、无 N+1（慢查询日志/MyBatis 日志核对单接口 SQL 条数为常数级）。
4. 例外登记：甘特/齐套类聚合页按 09 号 spec 口径（窗口 ≤92 天、织机百台×任务万级），H5 我的任务/我的领纱按 worker 索引，不单设阈值放宽，仍 <1s。
5. 灌数脚本与计时脚本放 `luna-srv/script/acceptance/perf/`，产出 Markdown 报告（接口/行数/P50/P95/P99/EXPLAIN 摘要），报告作为签字附件。

### 2.3 冒烟形态

- **API 自动冒烟**：JUnit 集成测试（沿用 luna-srv 现有测试基座与 Spring 测试库），包内按链路分四个顺序测试类，造数走 API（不走 DB 直插，除断言读库外）；链路内用例严格顺序、共享单据上下文；链路间允许各自重建库（见 2.1）。
- **UI 手工冒烟**：步骤+断言写死本 spec（§4 与 §8.4 引用），执行人逐项勾选并截图存档；打印类、浏览器兼容类、扫码类只走 UI。

### 2.4 账实零差异专项（贯穿四链）

- 库存：`lunaerp_stock_ledger` 只存流水，余额=实时 SUM；四链结束后对账——按"产品/纱线规格+单位+仓库"台账 SUM 与各业务单据累计量逐键相等，红冲/退货/发纱符号正确。
- 经营分录：`lunaerp_finance_ledger_entry` append-only——无 update/delete 端点（存在即 P1），尝试直改抛 LEDGER_IMMUTABLE；账户余额=条件更新物化值，重跑收款/付款后余额仍等于流水聚合。

## 4. 波次出口冒烟（W0–W3，不过闸不进下一波）

每波出口由该波各 spec 已冻结的冒烟要点汇编，执行人按序勾选；任一项失败阻断该波收口。

### W0 商业地基（common-foundation / module-gateway / approval-engine）

1. 回收站：主数据/草稿单据删除→列表可见→恢复→内容完整（BOM/产品/客户被引用时提示文案正确）；物理删除/恢复 XML 手写 SQL 带 tenant_id 专测通过。
2. Excel 导入：客户/供应商/产品/纱线四模板下载→合法文件导入成功→非法文件返回错误 Excel 且错误行定位准确；5000 行单事务在超时内完成。
3. 打印：布票标签批量打印，扫码跳转冻结落点（W4 链接不通期显示占位页）；发货单/装箱清单迁移后套打与二维码内容正确。
4. 消息：审批到达/通过/驳回三类模板触发，铃铛角标与点击跳转正确。
5. 脱敏肉眼核对：amount/contact 两类角色登录，列表、详情、导出、打印预览逐处核对（详见 §6.4）。
6. 模块网关：套餐移除"生产"→租户侧边栏无生产、直连路由重定向、API 返回 403 且文案为"模块未开通"；加回后刷新可见、历史数据完整。
7. 审批中心：待办/已办/抄送三视图 + 流程配置页；逐级/或签/会签（一票否决）/驳回/撤回/转交各跑一单；审批通过事件同事务副作用回滚验证。

### W1 售前链（cost-card / color-instruction / export-docs / release-production）

1. 纱价：两规格建价（含历史日期）→ Excel 导入→取价回退正确；同日重复拦截。
2. 成本卡：针织/梭织各建一卡→缺价拦截→补价生效（旧卡失效）→复制调价再生效；部分唯一索引并发兜底验证。
3. 报价：RMB 报价真毛利反算→修订出 v2→确认；USD 报价汇率快照→低价红字→转合同（预填草稿+来源列）→同号再转第二张合同不占量。
4. 打色：建单加 3 色→驳回 1 色重打→部分通过拦截确认→全过确认→胚布单引用自动投产；打印含全部轮次。
5. 出口单证：维护卖方资料→外销合同/发货单一键生成→补录→重新同步（只填空不覆盖）→定稿/回退→PI/CI/PL 三模板打印与完整门户 URL 二维码。
6. 下达生产：合同详情生产 Tab 选行改量→选 CONFIRMED 打色→下达→断言胚布单(ACTIVE)/染色单(ACTIVE)/胚布检验单(GREIGE/DRAFT) 同次生成、合同行 released_qty 累加；超下达与并发双开拦截；染色完成后手工生成成品检验单。

### W2 生产链（scheduling-material-check，并回归存量织造/染整/入库）

合同→下达生产→单据生成→织机就绪→排产中心派工（同织机时段冲突硬拦截，COMPLETED 豁免，无日期任务进待排池）→齐套试算（需求/库存/在途/两缺口与手工台账一致，含在途开关只改徽标）→缺配比/缺计划重量分区→外发建缸→排缸日历点击改期（COMPLETED 禁改）；甘特 50 织机×500 任务操作流畅；与生产进度页口径一致、互不回写。

### W3 资金闭环（customer/vendor reconciliation / sales-return / treasury）

建汇率→收款单审批过账+FIFO 自动分配→预收转核销→对账单生成/发送/代客确认/打印→账龄五桶下钻→发票申请登记；供应商侧：加工取数（COMPLETED 检验单、全等级计入、指纹防重）→对账单确认→付款申请审批→付款登记（部分付/多申请核销/预付抵扣）；报销一步过账（附件≤10）；工资单一月一单→次品扣款引用→审批→发放批次多次派生至已发清→零批次作废；转账/其他收支登记即终态；收支总览与毛利卡片空态/口径。

## 5. W4 四链全链 E2E 冒烟（API 自动 + 断言点）

通用断言约定：每个步骤断言 HTTP 状态/业务码 + 单据 DB 状态；链路关键节点追加台账/分录断言（§2.4）。枚举锚点：库存流水 txn_type=`STOCK_IN(+)/STOCK_IN_REVERSAL(-)/SHIPMENT_OUT(-)/YARN_OUT(-)`；分录 category=`AR_INC/AR_INC_REVERSAL/RECEIPT/RECEIPT_WRITE_OFF/ADVANCE_WRITE_OFF/AR_RETURN_REVERSAL/OUT_SUPPLIER/OUT_SUPPLIER_REVERSAL`。

### 5.1 主链路：报价→合同→下达→织造/染整/质检→入库→发货→签收→对账→收款

### 6.2 数据范围 4 档走查（仅销售归属链 5 表；依赖 21 号票）

组织构造：部门 D1（子部门 D1.1）、D2 平级；用户 m=D1 主管，a=D1 业务员，c=D1.1 业务员，d=D2 业务员；5 表数据按 owner_user_id 分布各人、按 dept_id 落部门。

| 档位 | 用例 | 断言 |
|---|---|---|

| 本部门及以下 | m（D1）查 | 见 a+c 不见 d；直接访问 d 的单据 id → 不存在类响应（不泄漏存在性） |

### 6.3 横向/纵向越权与租户隔离（全域必测）

**横向（跨租户/跨人，统一报"不存在"，禁止泄漏存在性）**

1. 每个有写接口的模块：A 租户用户持 B 租户单据 id 调 update/delete/状态动作/print-data → 不存在类错误；断言 DB 零变更。
2. 门户：客户 A token 访问客户 B 发货单/对账单（id 与 ?no= 双入口）→ 038-001；跨租户 token 同测；列表天然 customerId 过滤。
3. H5：工人 A token 操作工人 B 布票（开工/完工/异常）→039-002、操作 B 领纱单→039-006；检验员不受机台归属限制仅作用于质检功能。
4. 审批：非当前审批人操作 task →1_030_030_005；非本人 instance 不可见。
5. 回收站/手写 XML：他租户 bizId 恢复/物理删除不可达（XML 不经租户拦截器，专测守护）。
6. PortalTokenFilter 的 TenantContext ThreadLocal：并发请求串数据专测（结束必须清理）。

**纵向（无权限位）**

- 逐角色矩阵直连每个按钮对应 API：无权限位→403；菜单不可见+直连路由重定向。
- 仓管员调 :audit、业务员调 :delete、无 H5 角色调 H5 端点、未登录 401，各至少一例。
- 模块网关：未开通模块任意 API →403 且前端文案为"模块未开通"。

**租户隔离（写接口）**

- 全部 lunaerp 业务表 DO 继承 TenantBaseDO 清单核对（例外白名单：infra_config/@TenantIgnore 类必须登记理由，如卖方配置已改租户单行表）；
- 每模块写接口至少一条跨租户不可达用例；
- 字典表不租户隔离为已知接受项（18 号研究），验收备注确认。

## 8. 验收签字口径：什么叫"达到可对外售卖"

### 8.1 五个一票否决 gate

1. **G1 四链冒烟全绿**：5.1–5.4 API 自动冒烟在重建验收库一次跑通；5.5 UI 冒烟逐项勾选截图齐。
2. **G2 DoD 总表勾毕**：§3 全部 30 行（含 21 号票行）无空格——☐ 必须勾选、N/A/◐ 必须备注引用 spec 段落。
3. **G3 性能/安全硬指标全过**：P95 报告全接口达标且附 EXPLAIN；租户隔离/横纵向越权矩阵零失败；脱敏六类抽查零泄漏。
4. **G4 交付物齐**：干净机 compose 一键部署成功；§7 全部交付物到位；空库/存量库双库脚本重跑实证；默认数据按 §7.3 清点一致。
5. **G5 账实零差异**：库存台账与单据、分录账 append-only 与物化余额，四链终点对账 0 差异。

### 8.2 缺陷口径

- P0（数据错账/资金错误/数据泄漏/系统不可用）、P1（主链路阻断/守卫失效）：**清零**；
- P2（次要页面、规避路径明确）：允许 **≤10 个**，每个附规避说明并由客户书面知悉；
- P3 记录不阻断；安全类问题不提级豁免（任何越权/脱敏失败按 P0 计）。

### 8.3 验收阶段顺序

G4 环境就绪 → G2 静态核对（代码/脚本/文档）→ G3 性能安全 → G1 四链 → G5 账实复核 → 签字。前一 gate 不过不进入下一 gate。
