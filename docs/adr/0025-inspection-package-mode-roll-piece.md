# ADR-0025：检验单支持卷装/匹装双模式，完工交接只建表头、明细检验时产生

**状态**：Accepted
**日期**：2026-09-25
**关联**：生产管理-织造执行、生产管理-检验单；ADR-0014（明细独立子资源）、ADR-0023（布票每匹一码）、ADR-0024（布票回写 INSPECTED）

## 背景

参考系统的检验环节支持两种包装形态（卷装/匹装），而新项目检验单只有"按卷录检"一种模型：
明细以 `rollNo` 为卷号、一卷可含多匹（`pieceCount`）。织造布票是**每匹一码**——
若胚布检验只能按卷，则匹票交接后无法逐匹录检，中间断档。

参考系统的完工交接实际做法（经代码核实）：**只 find-or-create 检验单表头，不预生成任何录检明细**；
明细在检验工位扫码录检时才产生。但其表头写死"卷装"，与每匹一票自相矛盾。

## 决策

### 1. 主表增加包装模式 `package_mode`

字典 `lunaerp_inspection_package_mode`：`ROLL` 卷装（缺省，存量无感）/ `PIECE` 匹装。
由织造单"交接检验"生成的胚布检验单为 `type=GREIGE, package_mode=PIECE`。

### 2. 明细编号字段与唯一性

明细增加 `piece_no`（匹号，可空）平行字段。规则：

- **ROLL**：`rollNo` 必填、`pieceNo` 禁填；`pieceCount` 可 >1（一卷 N 匹）；单内 `(vatNo, rollNo)` 唯一。
- **PIECE**：`pieceNo` 必填；`rollNo` **可空可填且允许重复**——业务上一卷可拆成多个 pieceNo，
  此时多行共享同一 rollNo；单内唯一键为 `(vatNo, pieceNo)`。
- 两类唯一性均由 service 层校验，不建数据库唯一约束（沿用检验单用户决策）。
- PIECE 模式 `pieceCount` 恒 1 并隐藏：明细每匹一行，匹数=行数；防止按行数与按 pieceCount 双重统计导致产量翻倍，也防止出现没有 pieceNo 身份的黑户匹。

### 3. 布票血缘

明细增加 `weaving_ticket_id`（可空）：匹装明细由布票产生时回填，`pieceNo` 缺省取布票号、
`machineNo` 取布票 `actualMachine`、`vatNo` 空（胚布无缸号），重量/米数留待检验实测。
检验明细保存（有等级结果）后，后端按 `weavingTicketId` 将布票回写为 `INSPECTED`（ADR-0024）。

### 4. 交接检验 = find-or-create 表头，幂等

- 织造单侧点"交接检验"：按胚布单 ID 归一查找未删除的胚布检验单；有则复用，无则创建 PIECE 表头并带产品/合同/规格快照。
- 重复交接不建第二张单；已完工布票范围在返回信息中给出，检验工位可逐匹接单。
- 检验单 ACTIVE/COMPLETED 均可继续录明细；不回写织造单（除布票态外，遵循零回写惯例）。

### 5. 检验完成 → 生成胚布入库单（显式动作，P3）

检验单 COMPLETED 后，工作台提供"生成胚布入库单"按钮（权限独立，不挂检验单更新权限，同 ADR-0019 模式）：

- 从录检明细生成入库单（`type=PRODUCTION`）草稿明细：`batchNo/rollNo/pieceNo` 带出，
  仅 `grade != DEFECTIVE` 的明细带入（等外品通常另作处理，由仓管在入库单侧删行亦可）；
- 入库仓库由操作人在生成时选择；生成动作幂等（已生成过入库单的明细跳过）；
- **不自动生成**：是否入库、何时入库、入哪一仓的控制权留在现场。

## 与 ADR-0013 的关系

ADR-0013 延后的是旧系统"检验同步入库"的**自动紧耦合**链路（含财务锁、rollStatus 回写等）。
本期采用的是"显式生成独立入库单草稿 + 入库单自身审核过账"的松耦合路径，不复活旧同步服务；
检验单不引入 `SYNCED` 态——入库进度以入库单及其流水为准。

## 后果

- 双模式使明细表单与列表列需按模式切换渲染；导入/导出同样按模式分列。
- 一卷拆多匹时 rollNo 重复是设计内情形，任何按 rollNo 的统计需按模式区分语义。
- 等外品不带入入库单，如果业务上存在等外品也入库的场景，由仓管手工加行，不为此放宽默认规则。
