# ADR-0013：检验同步入库本期延后

**状态**：Accepted
**日期**：2026-09-21
**关联**：生产管理-检验单 MVP

## 背景

"生产管理-检验单 + 检验同步入库"是参考项目（linaagi）中已实现的一条完整业务链：检验指示单 → 逐卷录检 → 同步服务按"缸号+卷号"聚合 → 自动创建/更新 DRAFT 状态的入库单（stockIn + stockInItem），并带有金额重算、单价保留、财务锁、发货血缘保护等守卫。

新项目 lunaerp 目前**没有入库单模块**（stockIn/stockInItem/shipment/ledger 均未建）。若本期同时新建入库单模块，范围将显著扩大（需同时设计入库单主从表、状态机、与发货/台账的边界），且参考实现中入库单的下游守卫（财务对账锁、发货明细血缘）依赖尚未存在的 shipment/ledger 模块，无法在 MVP 闭环验证。

## 决策

本期 MVP **只做检验单自身**（检验单主表 + 录检明细 + 基本 CRUD + 状态机 + 编号规则），**不实现同步入库功能**，亦不新建入库单模块。同步入库作为后续独立 issue 推进，待入库单模块就绪后补做。

## 结果

- 检验单状态机本期不含 `SYNCED` 态（该态留给同步功能上线时插入），避免出现不可达的死状态。
- 检验单字段集去掉仅为同步服务的字段（unitPrice/packagingFee/productsJson/syncMetadata 等）。
- 前端工作区不设"同步记录"空 Tab。
- "同步入库"按钮与权限码可预留占位但默认禁用，待同步功能落地时启用。

## 反向权衡

- **不做完整闭环**：用户标题含"同步入库"，MVP 阶段无法演示检验→入库的真实数据流，业务闭环不完整。
- **后续插入成本**：同步功能上线时需补 `SYNCED` 状态、sync_log 表、与入库单模块的集成；但因本期检验单数据模型已按"可同步"设计（保留卷号/缸号/重量/米数等聚合所需字段），插入成本可控。
