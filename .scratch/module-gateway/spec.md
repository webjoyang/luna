# 横切基础 - 租户模块开通网关与菜单信息架构

Status: ready-for-agent（grilling 定稿，源自 `.scratch/lunaerp-commercialization/issues/03-module-gateway.md`）

## Problem Statement

商业化一期为私有化买断交付，不同客户购买的模块集合不同（如只买销售+库存、不买生产）。需要一个**模块开通网关**：租户只能看到/使用已开通的模块，未开通模块的菜单不可见、接口不可用。

芋道底座已有 `TenantPackage`（`system_tenant_package` 表，`menuIds Set<Long>`）可充当菜单级开通网关（见 18 号研究结论）：套餐定义菜单集合，租户绑定套餐后，`TenantServiceImpl#handleTenantMenu` 按套餐裁剪菜单、`MenuServiceImpl` 取菜单时按套餐过滤、改套餐时 `updateTenantRoleMenu` 自动同步租户管理员角色菜单。接口侧 `@PreAuthorize("@ss.hasPermission('...')")` 依赖用户角色的菜单 permission，套餐未含某菜单 → 角色拿不到该 permission → API 返回 403。

同时，现有 lunaerp 一级菜单分组（基本信息/业务管理/生产管理/库存管理/样品管理）与 Q18 决策的目标分组（基础信息/销售/生产/库存/样品/财务/审批中心 + 首页 + 系统管理）不一致，需要一次菜单 IA 迁移，并确定本图规划中各新模块的落位。

## Solution

**核心设计决策**（grilling 一轮锁定）：

1. **模块粒度 = 一级菜单目录**（`system_menu` 中 `type=1 AND parent_id=0` 的 lunaerp 目录）。**不另建 `lunaerp_module_catalog` 表**，模块全集即现有一级菜单目录 + 新增的财务/审批中心目录。套餐 `menuIds` 勾选一级目录 id 即开通该模块（其下所有子菜单/按钮通过菜单树级联纳入）。一期私有化买断场景下客户购买的是"销售/生产/库存"这类大块，二级菜单级开通由租户内 RBAC 负责，不在网关层做。
2. **不加后端模块拦截器**（Q2=C）。双层控制 = 前端菜单过滤（已有，TenantPackage 裁剪）+ 后端 `@PreAuthorize` 403（已有）。未开通模块的 API 因角色无对应 permission 而返回 403，前端将此场景提示为"模块未开通"。**不新增 `@ModuleActivation` 注解、不新增 `MODULE_NOT_ACTIVATED` 错误码**。
3. **停用 = 隐藏**（Q3=B）。停用时将该模块的整棵菜单树从套餐 `menuIds` 移除，租户用户完全看不到该模块，数据保留在库中但不可通过 UI 访问。重新开通 = 将菜单树加回套餐即可，无需数据迁移。
4. **菜单 IA 迁移**：现有分组改名/重组为 Q18 目标分组，**不设"供应链"分组**（Q4 决策）。纱线采购、发染记录归生产；供应商信息、入库管理保持原位。
5. **脱敏不在网关范围**（Q5）。字段级脱敏由 04 号 ticket 负责（芋道注解级脱敏 `@MobileDesensitize` 等），网关只管模块开/关，二者正交。

### 复用而非新建

本 spec **不新建任何数据库表、不新增后端拦截器、不新增 API**。全部复用芋道现有：

- 表：`system_tenant_package`（套餐）、`system_tenant`（租户→套餐关联）、`system_role_menu`（角色→菜单，由套餐同步）、`system_menu`（菜单树）
- 服务：`TenantPackageService`、`TenantService#handleTenantMenu/updateTenantRoleMenu`、`MenuServiceImpl` 套餐过滤
- 接口：`TenantPackageController`（套餐 CRUD）、`TenantController`（租户绑定套餐）
- 前端：`views/system/tenantPackage/index.vue`（套餐管理，已有菜单树勾选）

## 开通/停用流程

### 开通模块

1. 平台管理员在「系统管理 → 租户套餐」创建/编辑套餐，勾选目标模块的一级菜单（UI 自动级联勾选其下所有子菜单与按钮）。
2. 将套餐分配给租户（`system_tenant.package_id`）。
3. 系统自动执行 `TenantServiceImpl#updateTenantRoleMenu`：将套餐 `menuIds` 同步到该租户管理员角色的 `system_role_menu`。
4. 租户用户重新登录后，`MenuServiceImpl` 按套餐返回菜单树，前端渲染对应模块。

### 停用模块

1. 平台管理员编辑套餐，取消勾选目标模块的一级菜单（UI 自动级联取消其下所有子菜单与按钮）。
2. 系统自动同步：从租户角色的 `system_role_menu` 移除该模块整棵菜单树。
3. 租户用户刷新后，该模块从侧边栏消失；直接访问该模块 URL 时前端路由守卫重定向到首页或 404。
4. 该模块的 API 因角色无 permission，`@PreAuthorize` 返回 403；前端 axios 响应拦截器对 403 统一提示"无操作权限，如模块未开通请联系管理员升级套餐"。
5. 模块已有业务数据保留在对应业务表中（租户隔离），不做删除/归档；重新开通后立即可见可操作。

### 前端 403 处理约定

在 `luna-ui/src/utils/request.ts`（或现有 axios 拦截器）中，对 HTTP 403 响应：
- 若当前路由对应的菜单不在用户已加载菜单列表中（`permissionStore.getAddRouters` 不含该路由）→ 提示"该模块未开通，请联系管理员"并跳转首页；
- 若菜单存在但操作按钮级权限不足 → 提示"无操作权限"。

## 实施要点

### 后端（无新代码，仅配置/数据）

1. **菜单 SQL 迁移**：在各 `lunaerp-*.sql` 中，将一级目录的 `name` 改为新分组名（基本信息→基础信息、业务管理→销售、生产管理→生产、库存管理→库存、样品管理→样品），`id`/`parent_id`/`path` 保持不变。`path` 是否同步改（`/business`→`/sales`）由前端路由兼容决定，建议一期不改 `path` 以避免前端组件路径批量变更，仅改 `name`。
2. **审批中心菜单**：由 02 号 ticket 落地，一级菜单 ID 10800，`parent_id=0`，`path=/approval`。
3. **默认套餐**：在 `system_tenant_package` 种子数据中定义"核心包"套餐（勾选基础信息+销售+生产+库存+样品+财务+审批中心+系统管理+首页），新租户默认绑定。

### 前端

1. **侧边栏**：无需改动，菜单由后端按套餐返回，`routerHelper` 已根据 `name` 渲染。
2. **403 提示**：在 axios 响应拦截器中增加 403 分支（见上"前端 403 处理约定"）。
3. **租户套餐管理页**：复用芋道 `views/system/tenantPackage/index.vue`，确认菜单树勾选支持级联（父选子全选、父消子全消）。

### 不做的事（明确排除）

- ❌ 不建 `lunaerp_module_catalog` 表
- ❌ 不新增 `@ModuleActivation` 注解与 `ModuleActivationInterceptor`
- ❌ 不新增 `MODULE_NOT_ACTIVATED` 错误码
- ❌ 不做字段级脱敏配置（04 号 ticket）
- ❌ 不做二级菜单粒度的模块开通（租户内 RBAC 负责）
- ❌ 不做模块停用时的数据归档/删除
- ❌ 不设"供应链"一级分组
