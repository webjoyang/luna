# ADR-0020：撤销采用"冻结 + 克隆"留痕链，记录一律不可删

**状态**：Accepted
**日期**：2026-09-25
**关联**：生产管理-质检确认 MVP

## 背景

责任认定结果直接驱动挡车工工资扣款，"改判"是现场必然发生的事（初判设备故障、复查后认定操作失误等）。改判历史属于扣款凭据，必须可审计。

## 决策

质检确认记录三态：`PENDING` 待确认 / `CONFIRMED` 已认定 / `REVOKED` 已撤销。

- **确认**：仅 PENDING 可确认，写入责任类型、挡车工（OPERATOR 必填）、认定人、认定时间、备注。
- **撤销**：仅 CONFIRMED 可撤销。撤销时**旧行置 REVOKED 冻结、所有业务字段原样保留不清空**，同时按同一 `chainKey` **克隆一条全新 PENDING**（卷快照与挡车工随链带出，责任/认定字段重置为空）供重新认定。两条记录合起来构成一次完整改判的留痕。
- **一律不提供删除端点**（沿用参考系统口径）：PENDING / CONFIRMED / REVOKED 均不可删。
- 列表默认只呈现链上的有效行（PENDING/CONFIRMED）；REVOKED 行不进主列表，仅在该链详情的"认定留痕"区可查。

## 理由

- 单行覆盖或反复改态会丢失"谁在何时把责任认定成了什么、又被谁撤销"的凭据链；独立操作日志表只能记录字段 diff，读不出"这卷经历过几轮认定"的业务叙事。冻结+克隆让每一次认定都是不可变事实行，与库存流水"只增不改"的审计思路同构（ADR-0017）。
- 幂等生成（ADR-0019）以"该卷是否存在有效行"判定：撤销后克隆行即有效行，链永远完整；REVOKED 历史行不阻挡也不参与生成计数。

## 后果

- **误生成的待确认无法删除**（如录检时等级误选 B）。兜底通道是认定为 `WAIVED` 免扣结案——WAIVED 不进工资扣款汇总，不产生扣款后果。这是"零删除"政策刻意接受的代价。
- 同一卷物理上会有多行记录；任何按人/按日的统计口径都必须显式排除 REVOKED，工资汇总只取 CONFIRMED + OPERATOR。
- 手工登记（MANUAL）的记录提交即 CONFIRMED，撤销时同样克隆新 PENDING；链上无源单关联的行通过 `chainKey` 串联，不依赖源明细 ID。
